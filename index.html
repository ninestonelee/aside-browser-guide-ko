0. 이 매뉴얼에 대해

이 장에서 할 일: 이 매뉴얼이 누구를 위한 것인지, 어떤 순서로 읽으면 좋은지 확인합니다.

0.1 누구를 위한 매뉴얼인가

이 매뉴얼은 Aside를 처음 쓰는 한국어 사용자를 위해 만들었습니다. 직장인, 1인 사업자, AI 강의 수강생처럼 개발 지식이 없는 분도 따라 할 수 있게 썼습니다. 17장(개발자 도구)만 예외로, 터미널 명령을 다룹니다.

이 매뉴얼은 다음을 목표로 합니다.

  • 설치부터 첫 작업까지 10분 안에 끝낼 수 있게 안내합니다.
  • 매일 쓰는 기능(탭, 사이드 패널, 단축키)을 빠르게 익히게 합니다.
  • 반복 업무를 자동화(스킬, 메모리, 루틴)하는 방법을 설명합니다.
  • 권한, 비밀번호, 개인정보처럼 안전과 관련된 설정을 정리합니다.

공식 도움말의 순서입니다.

2.4 쓰던 브라우저 데이터 가져오기

가져오기를 하면 지금까지 쓰던 맥락을 그대로 가져와 바로 쓸 수 있습니다. 공식 도움말 기준으로 가져올 수 있는 것은 다음과 같습니다.

  • 방문 기록
  • 쿠키(로그인 상태 유지에 쓰임)
  • 북마크

현재 버전에서는 비밀번호도 가져올 수 있습니다. 공식 도움말에는 위 세 가지만 있지만, Settings > General > Import 설명(2026-11-17 화면)과 v1.0.1116.2 변경 이력에 비밀번호가 포함되어 있습니다.

일반 순서

  1. 가져오기 화면(첫 설정 또는 Settings > General > Import)을 엽니다.
  2. 가져올 프로필을 선택합니다. 프로필이 여러 개면 원하는 것을 고릅니다.
  3. 시스템 접근을 허용합니다.
  4. 가져오기가 끝날 때까지 기다립니다.
  5. 비밀번호 설정 단계로 넘어갑니다.

Safari를 쓰던 경우

Safari는 파일로 가져옵니다.

  1. Safari에서 File > Export를 선택합니다.
  2. 만들어진 ZIP 파일을 Aside의 가져오기 화면에 올립니다.
  3. ZIP이 아닌 파일은 거부됩니다(Please upload a ZIP file).

최신 버전(v1.0.1116.2)의 가져오기 개선 (공식 변경 이력)

  • 이전 브라우저의 여러 프로필을 한 번에 가져와 각각 별도의 새 Aside 프로필로 만들 수 있습니다. 북마크, 방문 기록, 비밀번호, 쿠키, 열린 탭, 탭 그룹, 확장 프로그램 중 지원되는 항목을 옮기고, 데이터 종류별 결과를 보여 줍니다.
  • macOS에서 Edge 프로필을 찾는 기능과 Windows에서 Dia 데이터 가져오기가 추가되었습니다.
  • 가져온 자동 입력(autofill) 정보를 바로 쓸 수 있습니다.

가져오기가 안 될 때

  1. 원본 브라우저의 프로필이 아직 있는지 확인합니다.
  2. 원본 브라우저가 파일을 독점하고 있다면 그 브라우저를 닫습니다.
  3. 파일 가져오기가 필요한 브라우저는 파일 방식을 씁니다.
  4. 다시 시도합니다.

Windows에서는 Chrome 창을 닫아도 프로세스가 남아 있는 경우가 많습니다. 작업 관리자에서 Google Chrome 프로세스를 모두 종료한 뒤 Try again을 누르세요. 더 자세한 내용은 19장에서 다룹니다.

  2. 맨 위 Aside works best as your default browser 옆의 Set as default를 누릅니다.

사이드바는 화면 왼쪽에 있습니다. 공식 이미지(그림 1-1) 기준으로 위에서 아래로 다음 영역이 보입니다.

  • 프로필: 현재 프로필을 보여 주고 바꿀 수 있습니다. 프로필 여러 개 쓰는 법은 4장에서 설명합니다.
  • Bookmarks: 접고 펼 수 있는 북마크 영역입니다.
  • Tabs: 열린 탭 목록입니다. 새 탭이 추가되는 위치는 Settings > Appearance > New tab position에서 정합니다(2026-11-17 화면의 값은 At top, 목록 맨 위).

  • Agent tabs: AI가 작업하며 연 탭이 모이는 곳입니다(3.7절).

Settings > Appearance > Customize sidebar에서 탭 위에 보일 영역(예: Chats, Bookmarks)을 고를 수 있습니다.

세로 탭과 가로 탭

탭은 세로(사이드바)와 가로(위쪽 탭 줄) 두 방식으로 쓸 수 있습니다. 방식은 Settings > Appearance > Tab style에서 고릅니다. 화면의 미리보기 그림 기준으로 San Francisco는 위쪽에 탭 줄이 있는 가로 탭, New York은 왼쪽 사이드바에 탭이 세로로 쌓이는 세로 탭입니다(화면 관찰 기준). 가로 탭은 v1.0.1116.2부터 창 크기에 맞춰 탭 폭이 줄어드는 방식이 기본입니다(이미 바꾼 설정은 유지).

팁: 사이드바를 숨기면 웹페이지를 넓게 볼 수 있습니다. ⌘S로 언제든 다시 열 수 있습니다.

3.4 채팅 목록

새 탭의 All Chats > 또는 사이드바의 Chats에서 전체 채팅 목록을 엽니다.

  • 맨 위에 새 탭 Ask와 같은 작업 입력창이 있습니다.
  • List(목록)와 Card(카드) 보기를 바꿀 수 있습니다.
  • 검색(Search tasks), 필터(Filter chats), 정렬(Sort tasks newest first)이 있습니다.
  • 각 카드에는 제목, 경과 시간(예: Working for 5m 9s), 마지막 답변 요약이 표시됩니다. 루틴이 만든 채팅에는 일정 배지(예: Everyday 9PM)가 붙습니다.

작업 화면과 대화 이어가기는 6장, 정리(Archive/Delete)는 6장과 19장을 참고하세요.

3.5 사이드 패널

사이드 패널은 웹페이지 오른쪽에 열리는 작업창입니다. 지금 보는 페이지를 작업 맥락으로 붙일 수 있습니다.

  • 단축키는 ⌥⇧B(Windows Alt+Shift+B)입니다. 공식 도움말이 아니라 확장 명령 Open Aside sidepanel의 기본값에서 확인한 값입니다(2026-11-17 화면 관찰).
  • 위쪽에서 채팅을 바꾸거나(New chat) 새 채팅을 시작하거나 패널을 닫습니다.
  • Settings > Agents > Ask Aside on tab switch에서 탭을 바꿀 때 New chat per tab(탭마다 새 채팅)으로 할지 현재 채팅을 유지할지 정합니다(7.4절).

자세한 사용법은 7장에서 다룹니다.

3.6 Ask Aside, New Task, 미니 팝업

Ask Aside (⌘E): 현재 탭에서 곧바로 작업을 시작합니다(단축키 설정 화면의 설명 Start a task from the current tab.). 지금 보는 페이지에 대해 묻고 싶을 때 가장 빠릅니다.

New Task (⇧⌘E): 새 작업을 엽니다. 페이지와 상관없는 일을 시작할 때 씁니다.

미니 팝업: 브라우저가 아닌 다른 앱을 쓰는 중에도 단축키로 여는 작은 채팅창입니다. 그림을 찍은 계정은 단축키가 ⌘P로 지정되어 있었습니다. 처음 설치했을 때의 기본값은 확인하지 못했으므로 아래 순서로 직접 확인하고 지정하세요.

  1. Settings > Mini popup을 엽니다.
  2. Enable Mini popup을 켭니다.
  3. Keyboard shortcut에서 원하는 단축키를 지정합니다.

공식 변경 이력에 따르면 미니 팝업은 끌어서 옮기고 크기를 조절할 수 있으며 Esc로 닫습니다. 다시 열면 위치와 크기가 유지됩니다. 팝업 안에서 ⌘N으로 새 세션을 시작하고, 파일 첨부와 @ 언급, 모델, 프로필, 프로젝트 선택도 할 수 있습니다.

주의: ⌘P는 보통 인쇄 단축키입니다. 미니 팝업에 ⌘P를 쓰면 인쇄와 겹칠 수 있으니 다른 조합으로 바꾸는 것을 고려하세요(4.7절).

3.7 에이전트 탭

AI가 작업을 하면서 연 탭은 Agent tabs로 묶여 보입니다. 사용자의 탭과 섞이지 않게 하려는 장치입니다.

  • 정리 시간: 작업이 끝난 뒤 AI가 연 탭을 자동으로 닫는 시간은 Settings > Agents > Clean up agent tabs에서 정합니다(그림을 찍은 계정의 값은 After 15 min).
  • 세로 탭과 가로 탭의 표시 차이 (공식 문제 해결 문서):
    • 앱 안에서 시작한 채팅의 탭은 세로 사이드바에 Agent tabs 줄이 생기지 않습니다. 그 채팅을 열면 나오는 브라우저 미리보기에서 봅니다.
    • CLI나 MCP를 쓰는 외부 AI 도구의 탭은 세로 사이드바의 Agent tabs 그룹에 모입니다.
    • 가로 탭에서는 Agent tabs 칩에 앱 안 채팅과 외부 도구가 연 탭이 모두 나올 수 있습니다.
  • Appearance에 Agent tabs를 보이거나 숨기는 스위치는 없습니다. 정리 시간 설정은 닫는 시점만 정하고 표시 위치는 바꾸지 않습니다.

팁: AI가 작업 중인 페이지를 직접 건드리면 작업이 꼬일 수 있습니다. 진행 중인 에이전트 탭은 보기만 하고, 고칠 일이 있으면 채팅으로 지시하세요(6장).

4. 브라우저로 쓰기: 기본기

이 장에서 할 일: 탭, 분할 화면, 프로필, 라쏘, 번역, 광고 차단, 외관, 단축키 등 매일 쓰는 브라우저 기능을 익힙니다.

4.1 탭 다루기

이름 바꾸기

  1. 탭을 우클릭하고 Rename을 선택합니다. 탭을 더블클릭해도 됩니다.
  2. 원하는 이름을 입력하고 저장합니다.
  3. 이름을 지우고 저장하면 페이지의 원래 제목으로 돌아갑니다.

세로 탭과 가로 탭 모두 지원합니다.

주소 복사: 탭을 우클릭하면 주소를 복사할 수 있습니다. 탭을 여러 개 선택한 뒤 한 번에 주소를 복사할 수도 있습니다(v1.0.1116.2). 현재 페이지 주소는 ⇧⌘C(Windows Ctrl+Shift+C)로 복사합니다.

탭 정리 (Tidy, Clear)

  • Tidy: AI가 열려 있는 탭을 묶고 이름을 붙여 정리합니다. 정리 중에는 회전 표시가 나타납니다. 묶는 방식은 Settings > Appearance > Customize Tidy Tabs의 Configure에서 조정하며, 묶는 기준을 직접 쓴 프롬프트(최대 300자)로 정할 수도 있습니다(변경 이력 기준).
  • Clear: 사이드바의 Clear를 누르면 먼저 확인을 묻습니다. 확인하면 현재 탭과 AI 탭을 제외한 다른 탭이 닫힙니다.

주의: Clear는 여러 탭을 한꺼번에 닫습니다. 작업 중이던 탭이 있는지 확인한 뒤 확인을 누르세요. 실수로 닫았다면 ⇧⌘T(Windows Ctrl+Shift+T)로 닫은 탭을 다시 엽니다.

탭 검색: ⇧⌘A를 누르면 열린 탭을 검색해서 이동합니다. 탭이 수십 개일 때 유용합니다.

탭 전환 순서: ⌃⇥(다음 탭)와 ⌃⇧⇥(이전 탭)로 전환합니다. 전환 순서는 Settings > Appearance > Tab switcher order에서 최근 사용 순과 사이드바에 놓인 순서 중에서 고릅니다(2026-11-17 화면의 값은 Recently used). 다음, 이전 탭 단축키도 바꿀 수 있습니다(4.7절).

비활성 탭 자동 닫기: Settings > Appearance > Close inactive tabs after에서 오래 안 쓴 탭을 방문 기록은 남긴 채 닫도록 정할 수 있습니다. 기본값은 Never(자동으로 닫지 않음)입니다.

4.3 프로필 (Profiles v2)

프로필은 탭, 로그인, 북마크 등을 분리해 쓰는 단위입니다. 예를 들어 업무용과 개인용을 나눌 수 있습니다. v1.0.1022.1부터 다음이 가능합니다.

  • 하나의 Aside 계정으로 여러 브라우저 프로필 사용
  • 프로필 만들 때 이름과 색상 선택. 다른 프로필의 북마크, 쿠키, 방문 기록, 확장 프로그램을 처음에 한 번 복사할 수도 있습니다. 복사 후 두 프로필은 서로 독립적입니다.
  • 계정에 연결된 프로필의 이름, 아이콘, 색상은 다른 기기에서 복원됩니다.
  • 프로필 메뉴에서 이름, 아이콘, 색상을 바꿉니다. v1.0.1116.2에서는 프로필과 탭 그룹 아이콘을 320종 중에서 고를 수 있습니다.
  • 세로 탭에서는 맥북 트랙패드에서 좌우로 쓸어 프로필을 바꾸고, 가로 탭에서는 프로필 아이콘을 눌러 바꿉니다(공식 변경 이력).

주의: 같은 계정으로 로그인한 모든 프로필은 채팅, 프로젝트, 루틴, 메모리를 함께 씁니다. 각 채팅은 실행한 프로필을 기억하고, 다른 프로필에서 열면 해당 프로필로 이동합니다(공식 문제 해결 문서). 로그아웃(Settings > Account > Sign out)은 현재 프로필에만 적용됩니다.

4.5 스크린샷, 번역, PiP, 광고 차단

스크린샷: Settings > General > Screenshot에 "우클릭 메뉴에서 현재 페이지를 캡처한다"고 적혀 있습니다. 변경 이력 기준으로 페이지를 우클릭해 Capture를 고르거나 ⌘⇧를 누른 채 끌어서, 보이는 화면, 페이지 전체, 마우스를 올린 요소, 자유 영역 중 하나를 잡습니다. 결과는 PNG로 복사하거나 내려받습니다.

  1. Settings > Security & Privacy를 엽니다.
  2. Adblock의 Manage filters에서 Configure를 누릅니다.
  3. 쓸 필터 목록을 추가합니다. 추가한 추천 필터 목록은 하나씩 끌 수 있습니다(변경 이력 기준).

Global setting은 새 채팅의 기본 권한을 정하는 설정(Settings > Agents > Access permission)으로 연결됩니다. 공식 도움말 기준 새 작업의 기본 권한 모드는 Guard입니다. 그림에 Full access가 보이는 것은 캡처한 계정이 기본값을 Full access로 바꿔 두었기 때문입니다. 처음에는 기본값 Guard 그대로 쓰세요. 권한 규칙과 샌드박스는 13장에서 자세히 다룹니다.

Incognito 작업

Incognito mode를 체크하면 일반 브라우저 프로필 상태(로그인 세션, 쿠키 등) 없이 작업합니다. 또 에이전트는 시크릿 세션에서 비밀번호 관리자(Vault)를 쓸 수 없습니다(공식 도움말: Agents cannot use password manager access in incognito sessions). 로그인이 필요한 일에는 맞지 않고, 로그인 없이 공개 자료를 조사하는 일에 알맞습니다.

5.4 Skip confirmation과 Ask first

입력창의 Skip confirmation 버튼을 누르면 Ask first와 Skip confirmation 두 가지를 고를 수 있습니다. 공식 도움말에는 설명이 없고, 화면 관찰 기준으로는 Aside가 진행하기 전에 먼저 물어볼지(Ask first), 묻지 않고 진행할지(Skip confirmation)를 고르는 항목으로 보입니다. 어떤 행동에 적용되는지는 공식 설명이 없으므로, 돈, 고객 정보, 삭제처럼 되돌리기 어려운 일은 Ask first를 고르고 권한 모드도 Guard 이하로 두세요.

6.3 승인 카드와 질문 카드 처리

  2. 카드가 주는 선택지 중에서 고르거나(확인, 승인 카드는 정해진 선택지만 제공) 질문에 답합니다.

주의: 카드의 내용을 읽지 않고 허용만 누르지 마세요. 결제, 전송, 삭제, 설정 변경처럼 되돌리기 어려운 행동은 특히 그렇습니다.

6.6 후속 메시지: Queue와 Steer

작업이 돌아가는 중에도 새 메시지를 보낼 수 있습니다. 새 메시지를 어떻게 처리할지는 Settings > Agents > Chat의 Follow-up behavior(후속 처리 방식)에서 정합니다(그림의 계정 값은 Queue).

방식 동작 언제 쓰나
Queue 새 메시지를 저장해 두었다가 현재 작업이 끝난 뒤 적용 지금 하는 일은 그대로 끝내고, 다음에 할 일을 추가할 때
Steer 새 메시지를 진행 중인 작업에 바로 넣어 방향을 바꿈 지금 당장 고쳐야 할 때: 다른 사이트를 쓰게 하거나, 행동을 멈추게 할 때

Queue 예시:

지금 하는 조사가 끝나면, 그 결과를 3줄 요약으로도 만들어 줘.

Steer 예시:

잠깐, 그 사이트 말고 공식 홈페이지에서 가격을 확인해 줘.

방금 하려던 삭제는 하지 마. 목록만 만들어서 보여 줘.

알아 두면 좋은 점(변경 이력 기준):

  • 대기 중인 메시지는 실행 전에 고치거나 끌어서 순서를 바꿀 수 있습니다.
  • 대기 중인 후속 메시지에도 첨부 파일이 유지됩니다.
  • 설정이 Queue여도, 에이전트가 답하는 중에 ⌘Enter로 보내면 그 메시지는 즉시 끼어드는 Steer로 들어갑니다. Windows 조합은 공식 문서에 없습니다.
  • Aside를 다시 시작해도 열려 있던 채팅과 대기 중인 후속 메시지는 유지됩니다.

잘못된 방향으로 가거나 중단하고 싶으면 작업을 멈춥니다.

  1. 작업이 진행 중일 때 입력창 오른쪽 끝의 검은 버튼이 정지 버튼(Stop, 네모 아이콘)으로 바뀝니다. 이 버튼을 누릅니다(그림 6-1 오른쪽 아래).
  2. 실행이 곧바로 멈추고, 그 작업이 부른 하위 에이전트도 함께 멈춥니다. 대기 중이던 후속 메시지는 일시정지되며, 재개 동작으로 다시 실행할 수 있습니다(변경 이력 기준).
  3. 이미 일어난 일(보낸 메일, 바뀐 설정)은 되돌려지지 않습니다. 멈춘 뒤 상태를 직접 확인하세요.

팁: 멈추기보다 Steer로 "하던 일을 중단하고 지금까지 한 일만 요약해 줘"라고 보내는 방법도 있습니다.

6.8 채팅 목록 관리

Chats 화면(All Chats)에서 지난 작업을 관리합니다.

기능 설명

Search tasks 채팅을 검색합니다. 사이드바에서도 지난 채팅을 검색할 수 있습니다(변경 이력 기준)
Filter chats 상태나 프로젝트로 거릅니다. 프로젝트는 여러 개를 한꺼번에 고를 수 있습니다(변경 이력 기준)
Sort tasks 정렬 기준(2026-11-17 화면: newest first, 최신순)
카드 채팅 제목, 경과 시간, 마지막 답변 요약. 루틴이 만든 채팅은 일정 배지(예: Everyday 9PM)가 붙습니다

고정(pin), 읽음 표시, 보관, 삭제는 사이드바 채팅의 우클릭 메뉴에서 합니다. 고정한 채팅은 사이드바와 작업 목록 맨 위에 남습니다. 새 탭의 Chats, Routines 탭에는 읽지 않은 항목 배지가 표시됩니다(변경 이력 기준).

6.9 보관과 삭제의 차이

구분 보관 (Archive) 삭제 (Delete)
채팅 목록에서 빠지지만 남아 있음 영구 삭제
하위 채팅, 파일 유지 하위 에이전트와 사이드 채팅, 세션 폴더, 대화 기록, 첨부, 그 폴더에 저장된 파일까지 삭제

복원 가능 불가능
내가 따로 연결한 작업 폴더 유지 삭제되지 않음

복원 방법:

  1. Settings > Archived chats를 엽니다.
  2. 복원할 채팅을 엽니다.
  3. Unarchive를 누릅니다. 사이드바의 날짜순 위치는 그대로 유지됩니다(변경 이력 기준).

주의: 루틴(11장)을 만든 채팅을 정리할 때는 보관과 삭제 중 무엇이 맞는지 먼저 생각하세요. 삭제하면 그 루틴도 영구히 사라집니다. 확신이 없으면 보관하세요.

7. 사이드 패널: 지금 보는 페이지로 일 시키기

이 장에서 할 일: 지금 보고 있는 페이지를 근거로 작업을 시작하는 사이드 패널의 사용법과, 페이지가 필요한 일에 바로 쓸 수 있는 지시문 예시를 익힙니다.

7.1 언제 쓰나

사이드 패널은 "지금 보는 페이지가 작업의 근거가 되어야 할 때" 씁니다. 청구서 페이지에서 서류를 받거나, 고객 문의 화면에서 답장 초안을 쓰거나, 계약서 페이지에서 날짜를 뽑는 일처럼, "이 페이지"라고 말하면 끝나는 일에 알맞습니다.

7.2 여는 법

방법 내용
단축키 ⌥⇧B(Windows Alt+Shift+B). 공식 도움말에는 없고, 확장 명령 Open Aside sidepanel의 기본값으로 확인한 값입니다(2026-11-17 화면 관찰)
단축키 바꾸기 Settings > Appearance > Keyboard shortcuts 맨 아래 Extension shortcuts(Aside 확장 프로그램 단축키 관리)에서 바꿉니다(화면 관찰 기준, 4.7절)

화면 위쪽에는 New chat(채팅 전환), 새 채팅 아이콘, 닫기(Close side panel)가 있고, 아래쪽 입력창에는 +, Skip confirmation(아이콘), 모델, Ultrabrowse, 마이크가 있습니다.

7.3 페이지 첨부

  1. 작업의 근거로 삼을 페이지를 엽니다.
  2. 사이드 패널을 엽니다.
  3. 입력창 위에 현재 페이지가 첨부된 모습을 확인합니다. 첨부에는 페이지 제목과 호스트(사이트 주소)가 표시됩니다.
  4. 작업을 쓰고 보냅니다.

페이지 없이 시작하고 싶으면 첨부를 빼세요. 그러면 Aside가 그 페이지를 읽지 않고 시작합니다.

주의: 첨부한 페이지에는 개인정보나 고객 정보가 들어 있을 수 있습니다. 그 정보를 쓰지 않아도 되는 일이라면 첨부를 빼고 시작하세요.

7.4 탭을 바꿀 때의 동작

탭을 바꿨을 때 사이드 패널이 어떻게 반응할지는 Settings > Agents > Ask Aside on tab switch에서 고릅니다.

선택 동작
New chat per tab 탭을 바꾸면 그 탭에 맞는 새 채팅으로 시작(그림의 계정 값)
현재 채팅 유지 탭을 바꿔도 지금 채팅을 그대로 이어감. 현재 탭을 가리키는 탭 칩은 옮겨 간 탭을 따라감(변경 이력 기준)

두 번째 선택지의 화면 문구는 수집하지 못했으니 목록에서 New chat per tab이 아닌 쪽을 고르세요.

7.5 초안은 페이지별로 저장됩니다

사이드 패널에 쓰던 글(초안)은 페이지 맥락별로 저장됩니다. 페이지를 떠났다가 돌아오면 처음 시작한 탭에 초안이 남아 있을 수 있습니다. 변경 이력 기준으로, 초안, 음성 입력, 전송은 쓰던 탭에 머무르도록 고쳐져 있습니다. 보내지 않은 초안은 페이지 이동 후에도 보존됩니다.

7.6 활용 예시 5개

공식 도움말의 예시를 우리 상황에 맞게 바꾼 것입니다. 모두 "이 페이지"를 기준으로 하고, 위험한 단계 앞에서 멈추는 제약을 넣었습니다.

예시 1. 로그인 후 서류 받기

이 급여 관리 페이지에서 내 저장된 로그인 정보로 로그인해서 이번 달 급여명세서 PDF를 받아 Downloads 폴더에 저장해 줘.
추가 인증이나 인증 코드가 필요하면 멈추고 나에게 알려 줘.

예시 2. 청구서 모으기

이 결제 내역 페이지에서 최근 3개월 청구서와 영수증을 찾아 PDF로 내려받아 줘.
파일 이름은 "청구일_업체명" 형식으로 바꾸고, 결제 설정은 절대 바꾸지 말고 멈춰.

예시 3. 고객 문의 답장 초안

이 고객 문의 화면과 연결된 계정 페이지를 보고 문제가 무엇인지 정리한 뒤, 정중한 답장 초안을 써 줘.
내부 후속 조치가 필요하면 목록으로 따로 알려 줘. 답장은 보내기 전에 멈춰.

예시 4. 계약서 날짜 추출

이 계약서 페이지에서 갱신일, 해지 통보 기한, 청구 담당자, 통지 기간을 찾아 표로 정리해 줘.
앞으로 60일 안에 도래하는 항목은 따로 표시해 줘. 원문에 없는 항목은 "없음"이라고 적어.

예시 5. 대시보드 요약

이 대시보드에서 지난주와 달라진 지표를 찾아 짧게 요약해 줘.
담당자가 필요한 항목은 할 일 초안 목록으로 만들고, 실제로 등록하기 전에 멈춰.

7.7 사이드 패널과 작업 페이지, 무엇을 고를까

상황 사이드 패널 새 탭 / Chats 화면
지금 보는 페이지가 근거 알맞음 페이지 주소를 직접 적어야 함

8. 프로젝트

이 장에서 할 일: 반복되는 주제의 일을 하나의 공간에 모으는 프로젝트(Project)를 만들고, 채팅을 넣고 빼는 방법을 익힙니다.

8.1 프로젝트란

프로젝트는 "자기만의 파일, 지침, 로컬 작업 공간이 필요한 일"을 위한 전용 공간입니다. 변경 이력 기준으로 다음을 할 수 있습니다.

  • 이름, 아이콘, 색, 작업 폴더(workspace folder)를 정해 만들고, 작업 입력창에서 선택합니다.
  • 프로젝트 페이지에서 원본 파일(source files)을 추가하고, 프로젝트 전용 AGENTS.md 지침을 편집합니다.
  • 그 프로젝트의 작업을 한곳에서 보고, 프로젝트를 오가고, 끝난 프로젝트를 보관합니다. 보관해도 작업과 루틴은 지워지지 않습니다.
  • 프로젝트 메모리(Project memory), 연결된 작업 경로 표시(breadcrumb)가 있습니다.
  • 같은 계정, 같은 프로젝트의 작업끼리는 서로 찾고 메시지를 보낼 수 있습니다. 권한이 더 높은 작업에게 보낼 때는 먼저 묻습니다.

8.2 만들기

방법 1. 설정에서 만들기

  1. Settings > Projects를 엽니다 (프로젝트는 설정의 독립된 페이지로 분리되어 있습니다).
  2. Create를 누릅니다.
  3. Create Project 창이 열립니다. 설명은 Group related tasks, routines, and working context.(관련된 작업, 루틴, 작업 맥락을 묶습니다)입니다.
  4. Name에 이름을 쓰고, 옆의 버튼으로 아이콘과 색을 고릅니다.
  5. Working directory(작업 폴더)를 정합니다. 기본값은 ~/.aside/u/<계정>/projects/... 아래이고, Choose folder로 내 컴퓨터의 기존 폴더를 지정할 수 있습니다.
  6. Create를 누릅니다. 취소는 Cancel입니다.

목록의 각 프로젝트 오른쪽에는 ...(actions) 메뉴가 있습니다. 2026-11-17 화면에서 이 메뉴의 항목은 Archive(보관) 하나입니다(8.8절).

방법 2. 입력창에서 만들기

작업 입력창의 Project 버튼 또는 + > Projects에서 고릅니다.

선택 의미
(프로젝트 이름) 이미 있는 프로젝트에 이 작업을 넣음
Use an existing folder 내 컴퓨터의 기존 폴더를 작업 공간으로 삼아 시작(화면 관찰 기준)
Start from scratch 빈 상태에서 새로 시작

8.3 프로젝트 안에서 채팅 시작

  1. 입력창의 Project 버튼에서 프로젝트를 고릅니다.
  2. 평소처럼 작업을 씁니다.
  3. 새 채팅은 그 프로젝트의 작업 목록에 쌓입니다. Chats 화면에서는 프로젝트로 걸러 볼 수 있습니다(여러 프로젝트 선택 가능).

8.4 기존 채팅을 프로젝트에 넣고, 옮기고, 빼기

프로젝트 없이 시작한 채팅도 나중에 정리할 수 있습니다 (변경 이력 기준).

  • 위치: 채팅 메뉴, 작업 메뉴, 입력창의 Project 알약(pill)에서 모두 가능합니다.
  • 하위 채팅은 상위 채팅과 함께 이동합니다.
  • 이미 다른 프로젝트에 속한 채팅은 옮기기 전에 확인을 묻습니다.
  • 이 메뉴에서 새 프로젝트를 바로 만들 수도 있습니다.

8.5 작업 폴더와 파일 권한의 관계

프로젝트의 작업 폴더(project root)는 Aside가 일하는 기본 장소입니다. Settings > Agents > File permissions에서 이 폴더가 Can view(보기만)와 Can edit(만들기, 고치기, 지우기) 목록에 기본으로 포함됩니다 (2026-11-17 화면 기준). 편집 가능 폴더 목록은 작게 유지하라는 안내가 화면에 있습니다. 권한 모드 Guard는 허용한 폴더 밖에 접근할 때 묻습니다. 자세한 규칙은 13장입니다.

8.6 프로젝트 전용 스킬 폴더

프로젝트 전용 스킬 폴더는 공식 문서와 2026-11-17 화면 어디에도 설명이 없습니다. 프로젝트에서만 지킬 규칙은 프로젝트 지침(AGENTS.md, 8.1절)에 적고, 여러 작업에서 되풀이할 작업 방식은 스킬(9장)로 만드세요.

8.7 채널과 프로젝트

채널(Slack, Telegram, Discord 연결)을 프로젝트에 묶으면, 그 채널로 들어온 작업은 해당 프로젝트의 작업 공간과 메모리를 함께 씁니다(공식 채널 도움말: 연결을 프로젝트에 묶으면 채널 작업이 그 프로젝트의 작업 공간과 메모리를 공유). 묶지 않으려면 No project를 고릅니다. 설정 방법은 16장입니다.

8.8 보관한 프로젝트 삭제

끝난 프로젝트는 Settings > Projects 목록에서 프로젝트 오른쪽 ... 메뉴의 Archive로 보관합니다. 보관해도 작업과 루틴은 그대로 남습니다. 보관한 프로젝트는 삭제할 수 있습니다(변경 이력 기준). 삭제할 때 프로젝트의 채팅, 루틴, 파일, 메모리가 어떻게 처리되는지는 공식 문서에 설명이 없습니다 [확인 필요]. 필요한 파일은 삭제 전에 따로 보관하세요.

주의: 보관이 되돌릴 수 있는 방법, 삭제는 되돌릴 수 없는 방법이라고 생각하고 고르세요(6.9 참고). 확신이 없으면 보관하세요.

8.9 운영 요령

  • 반복되는 주제 하나당 프로젝트 하나를 만드세요. 주제가 섞이면 지침과 메모리도 섞입니다.
  • 프로젝트 이름은 나중에 검색하기 쉽게 짧고 구체적으로 정합니다.
  • 프로젝트 지침(AGENTS.md)에는 "항상 지킬 규칙"(말투, 저장 위치, 하면 안 되는 일)을 적고, 매번 달라지는 내용은 작업 지시문에 적습니다.
  • 작업 폴더에 필요한 파일만 넣고, 폴더 권한은 필요한 만큼만 주세요.

9. 스킬: 일하는 방법을 가르쳐 두기

이 장에서 할 일: 스킬이 무엇인지 알고, 내가 자주 하는 작업을 스킬로 만들어 "한 줄 요청"으로 끝내는 상태를 만듭니다.

9.1 스킬이란

스킬(Skill)은 특정 작업의 절차와 지식을 적어 둔 설명서입니다. 사람으로 치면 업무 매뉴얼에 해당합니다. Aside는 작업을 하다가 필요하면 해당 스킬을 읽고 그 순서대로 따릅니다.

스킬이 있으면 좋은 점은 세 가지입니다.

  • 같은 설명을 매번 다시 하지 않아도 됩니다.
  • 작업 결과의 모양과 품질이 일정해집니다.
  • 실패한 지점을 스킬에 적어 두면 다음부터 같은 곳에서 막히지 않습니다.

팁: 메모리(10장)는 "나는 이런 사람이고 이런 취향이다"를 기억하는 곳이고, 스킬은 "이 일은 이 순서로 한다"를 적어 두는 곳입니다. 규칙과 취향은 메모리에, 작업 절차는 스킬에 두면 역할이 겹치지 않습니다.

9.3 스킬 쓰는 법

스킬을 쓰는 방법은 세 가지입니다.

  1. 그냥 요청하기. "이번 주 받은 메일 중 견적 요청만 정리해줘"처럼 평소대로 말하면 Aside가 알아서 맞는 스킬을 고릅니다. 가장 편한 방법이고 대부분은 이것으로 충분합니다.
  2. 이름을 말해 지정하기. "블로그 글쓰기 스킬로 초안 써줘"처럼 스킬 이름이나 용도를 말하면 그 스킬을 우선해서 씁니다. 스킬이 여러 개 비슷할 때 유용합니다.
  3. 입력창 슬래시 메뉴. 작업 입력창에서 /나 $를 입력하면 Skills 목록이 나타납니다(그림 9-2, 2026-11-17 화면 확인. 변경 이력: "Shows skills in slash rich input"). 목록에서 고르면 입력창에 스킬 칩이 붙어 그 스킬을 분명하게 지정할 수 있습니다. 루틴의 지시 내용 칸에서는 $로 스킬을 부릅니다(화면 안내 문구 "Use $ to mention skills", 11장).
/Google Sheets 이 시트의 이번 달 매출 합계를 계산하고, 지난달과 비교해서 표로 보여줘.

참고: 스킬 설정을 바꾸면 이미 열려 있는 채팅에도 바로 적용됩니다(변경 이력 기준).

9.4 내 스킬 만들기

내가 만든 스킬은 My Skills에 모입니다. 가장 쉬운 방법은 일을 한 번 제대로 끝낸 직후, 그 과정을 스킬로 만들어 달라고 요청하는 것입니다. 이때 System 스킬인 Skill Creator(스킬 만들기 도우미)가 쓰입니다.

  1. 평소처럼 작업을 맡기고, 결과물이 마음에 들 때까지 대화로 다듬습니다.
  2. 같은 채팅에서 아래 프롬프트를 입력합니다.
  3. Aside가 만든 스킬의 이름, 설명, 단계를 읽어 보고 빠진 내용이 있으면 말로 보충합니다.
  4. Settings > Plugins & MCPs > Skills의 My Skills에 생겼는지 확인합니다.
방금 한 작업 과정을 스킬로 만들어줘. 잘 된 점, 막혔던 점, 최종 체크리스트 포함해서.

처음부터 설계해서 만들 수도 있습니다.

거래처에 보내는 견적 안내 메일을 쓰는 스킬을 만들어줘.
- 말투: 정중하지만 부담스럽지 않게, 짧은 문단
- 반드시 들어갈 것: 견적 유효기간, 결제 조건, 담당자 연락처
- 끝나면 보내기 전에 나에게 초안을 먼저 보여줄 것

주의: 스킬에 비밀번호, 카드번호, 주민등록번호 같은 민감한 값을 적지 마세요. 스킬은 파일로 저장되어 이후 작업에서 계속 읽힙니다.

9.5 스킬 가져오기(Import)

Skills 화면 오른쪽 위의 Import 버튼(옆에 펼침 화살표가 있음)으로 이미 가지고 있는 스킬을 가져올 수 있습니다. 가져올 수 있는 파일 형식과 폴더 구조는 공식 도움말에 설명이 없으니, Import를 눌러 화면 안내를 따르세요. 외부에서 받은 스킬은 내용을 먼저 읽어 보고, 의도하지 않은 지시가 들어 있지 않은지 확인한 뒤 쓰세요.

9.6 스킬 다듬기

스킬은 한 번 만들고 끝이 아닙니다. 쓰다가 막히거나 결과가 어색하면 그 자리에서 스킬에 반영하도록 요청합니다.

이번에 막힌 부분을 스킬에 반영해줘. 다음에는 같은 곳에서 멈추지 않도록 확인 단계를 추가해줘.

방금 결과에서 제목이 너무 길었어. 제목은 25자 이내로 하라는 규칙을 그 스킬에 추가해줘.

실패할 때마다 한 줄씩 보태면 스킬이 점점 내 업무에 맞게 단단해집니다. 스킬이 여러 개로 늘어나 헷갈리면 "내 스킬 목록을 용도별로 정리해서 보여줘"라고 요청해 점검하세요.

9.7 스킬은 어디에 저장되나

종류 위치 비고
계정 스킬 Aside 폴더(Mac ~/.aside, Windows %USERPROFILE%\.aside) 안 모든 프로젝트에서 쓸 수 있습니다. 사용자 스킬이 Aside 폴더에 저장된다는 점은 공식 도움말 "Use Aside on multiple devices"에 나옵니다. 작성 환경(Mac)에서는 계정 폴더 아래 skills 폴더에 있었습니다(공식 도움말에 설명 없음, 관찰 기준).
프로젝트 스킬 프로젝트 폴더의 .agents/skills/ 그 프로젝트 작업에서 쓰는 전용 스킬입니다. 공식 문서에는 없는 구조로, 작성 환경에서 관찰한 내용입니다. 동작 범위는 [확인 필요]

중요한 점은 스킬이 기기 간에 동기화되지 않는다는 것입니다. 공식 도움말에 따르면 메모리, 사용자 스킬, 에이전트 지침 파일은 각 컴퓨터의 Aside 폴더에 있고 동기화되지 않습니다. 다른 컴퓨터에서도 같은 스킬을 쓰려면 그 컴퓨터에서 다시 만들거나 Import로 가져와야 합니다. Aside 폴더를 통째로 복사하는 방법은 지원되지 않습니다. 자세한 내용은 18장을 보세요.

9.8 외부 에이전트 앱에 Aside 스킬 추가하기

Settings > Developers(설정 > 개발자)의 Skill & MCP 영역에는 Aside Skills와 Add skill to... 버튼이 있습니다. 이것은 Codex, Claude Code 같은 외부 에이전트 앱에 Aside를 다루는 스킬을 붙여 주는 기능입니다. 화면 설명은 "Agent apps share local runtime skills; custom profiles and remote hosts need separate setup"(에이전트 앱은 로컬 런타임 스킬을 공유하며, 사용자 지정 프로필과 원격 호스트는 별도 설정이 필요함)입니다.

Aside 안에서만 일한다면 이 설정은 건드릴 필요가 없습니다. 자세한 내용은 17장을 보세요.

9.9 스킬과 MCP, 무엇이 다른가

구분 스킬 MCP
정체 일하는 방법을 적은 설명서 외부 도구와 앱을 연결하는 통로
용도 "이 일은 이렇게 해"를 가르침 Aside가 데스크톱 앱 등 외부 도구를 직접 다루게 함
필요한 때 반복 작업의 품질과 일관성을 높일 때 웹사이트만으로 안 되는 앱과 연동할 때

Settings > Plugins & MCPs > MCPs 화면에는 "Aside understands and works with websites without MCPs"(Aside는 MCP 없이도 웹사이트를 이해하고 다룬다)라는 안내가 있습니다. 대부분의 사용자는 MCP보다 스킬을 먼저 쓰게 됩니다. MCP는 17장에서 다룹니다.

9.10 좋은 스킬 후보 고르는 법

다음 중 하나라도 해당하면 스킬로 만들 만합니다.

  • 같은 설명을 두 번 했다. 가장 확실한 신호입니다.
  • 결과물의 형식이 정해져 있다(블로그 글, 견적 메일, 회의록, 주간 보고).
  • 매번 확인해야 하는 체크리스트가 있다.
  • 한 번 실패했던 지점이 있어 같은 실수를 막고 싶다.
  • 다른 사람에게 일을 넘길 때 쓰는 인수인계 문서가 있다.

반대로 한 번만 하는 일, 매번 조건이 완전히 달라지는 일은 스킬보다 그때그때 요청하는 편이 낫습니다.

10. 메모리와 Context Awareness

이 장에서 할 일: Aside가 나를 기억하는 방식을 이해하고, 규칙을 기억시키고, 잘못된 기억을 고치며, Context Awareness를 켤지 판단합니다.

10.1 메모리가 하는 일

메모리(Memory)는 Aside가 방문 기록, 채팅, 작업에서 얻은 맥락을 다시 쓰게 해 주는 기능입니다. 덕분에 "지난번처럼 해줘"라고 말해도 배경을 처음부터 설명하지 않아도 됩니다.

공식 도움말 기준으로 메모리를 켜 두면 다음이 가능합니다.

  • 방문 기록을 맥락으로 사용
  • 채팅과 작업 활동에서 새 메모리 생성

메모리를 끄면 새 채팅과 작업이 메모리를 만들지 않습니다.

10.2 Settings > Memory 둘러보기

Settings > Memory(설정 > 메모리)에는 네 개의 화면이 있습니다. Context Awareness는 10.7절에서 따로 설명합니다.

화면 하는 일
Overview 저장된 메모리 파일을 트리로 보고, 파일을 열어 내용을 확인하고, Edit으로 직접 고칩니다. Open folder로 메모리 폴더를 컴퓨터에서 바로 엽니다.
History 메모리가 언제 어떻게 바뀌었는지 변경 이력을 봅니다.
Context Awareness 브라우저와 앱 활동 캡처를 켜고 끕니다. New 표시가 붙어 있습니다.
Configure 메모리 상태 확인, 다시 만들기, 켜고 끄기, 보관 기간 설정.

Overview에는 날짜별 일지 파일(episodic/ 폴더)과 주제별 문서가 보입니다(2026-11-17 화면 기준). 파일은 사람이 읽을 수 있는 텍스트라서, 무엇이 기억되어 있는지 직접 확인할 수 있습니다.

10.3 Configure 항목

항목 설명
상태 표시 Running normal(정상 작동) 같은 상태와 마지막 갱신 시각, 저장된 조각(chunks) 수가 보입니다.
Rebuild 메모리 색인을 처음부터 다시 만듭니다. 변경 이력에 따르면 Retry는 진행 상황을 보존하고, Rebuild는 처음부터 다시 시작합니다. 평소에는 누를 일이 거의 없습니다.
Enable memories "Generate new memories from chats"(채팅에서 새 메모리 생성) 스위치. 끄면 새 메모리가 만들어지지 않습니다.
Episodic memory retention 날짜별 관찰 일지를 얼마나 보관할지 정합니다. 선택지는 Never forget(계속 보관), 30 days, 90 days입니다. 기본값은 Never forget입니다(2026-11-17 화면 기준).

팁: 일상적인 관찰 기록을 빨리 잊게 하고 싶다면 30 days나 90 days처럼 짧은 보관 기간을 고르세요. 보관 기간이 적용되는 대상은 날짜별 관찰 일지(episodic memory)입니다.

Settings > Models의 Task models에서 메모리 관련 작업에 쓰는 모델도 확인할 수 있습니다. 화면 설명에 따르면 Fast 모델은 "side work, summaries, and memory extraction or dreaming"(부수 작업, 요약, 메모리 추출과 정리)을, Standard 모델은 "memory reorganization"(메모리 재정리)을 맡습니다. 모델 선택은 12장을 보세요.

10.4 기억시키는 요령: 규칙 형태로 말하기

메모리는 막연한 감상보다 구체적인 규칙일 때 잘 쓰입니다. "앞으로", "항상", "하지 마" 같은 말로 적용 범위를 분명히 하세요.

약한 예 강한 예
나는 짧은 글이 좋아 앞으로 내 블로그 초안은 문단당 3문장 이내로 쓰고, 소제목은 질문형으로 달아줘. 이 규칙을 기억해줘.
존댓말로 써줘 거래처 메일은 항상 "~합니다" 체로 쓰고, 마지막에 내 이름과 연락처 서명을 넣어줘. 기억해줘.
보고서 형식은 알지? 주간 보고는 항상 "이번 주 한 일, 다음 주 할 일, 막힌 점" 3단 구조로 써줘. 기억해줘.
결제는 조심해 결제와 송금은 절대 혼자 진행하지 말고, 최종 단계 전에 반드시 나에게 확인받아줘. 기억해줘.

팁 세 가지입니다.

  • 한 번에 규칙 하나씩 말하고, 마지막에 "기억해줘"라고 덧붙입니다.
  • 이유를 한 줄 붙이면 더 정확하게 적용됩니다. ("고객이 모바일로 읽기 때문에")
  • 한 번만 쓸 지시는 기억시키지 말고 그 작업 안에서만 말하세요.

10.5 점검하고 고치기

잘 쌓이고 있는지 한 달에 한 번쯤 점검하세요. 채팅에서 이렇게 요청합니다.

내 메모리에 저장된 규칙을 정리해서 보여줘. 오래됐거나 서로 충돌하는 항목이 있으면 따로 표시해줘.

잘못 기억된 내용을 고치는 방법은 두 가지입니다.

  1. 채팅으로 요청하기. 예: "내가 블로그 글을 3문장 이내로 쓴다고 기억하고 있는데, 지금은 4문장 이내로 바뀌었어. 메모리를 고쳐줘."
  2. Overview에서 직접 고치기. Settings > Memory > Overview에서 해당 파일을 열고 Edit을 눌러 내용을 수정합니다. 고친 뒤 History에서 변경 이력이 남았는지 볼 수 있습니다.

팁: 틀린 기억을 발견하면 바로 고치세요. 틀린 규칙은 이후 작업에 계속 영향을 줍니다. 필요 없는 항목은 지워 달라고 요청하거나 Overview에서 직접 정리합니다.

10.6 메모리와 개인정보, 기기 간 동기화

  • 메모리는 기기 간에 동기화되지 않습니다. 공식 도움말에 따르면 메모리, 사용자 스킬, 에이전트 지침 파일(AGENTS.md, SOUL.md)은 각 컴퓨터의 Aside 폴더(Mac ~/.aside, Windows %USERPROFILE%\.aside)에 있습니다. 컴퓨터가 두 대라면 각각 따로 기억을 쌓습니다.
  • 메모리 파일은 컴퓨터 안에 일반 텍스트로 있으므로 Overview에서 모두 읽을 수 있습니다. 민감한 정보(주민등록번호, 카드번호, 비밀번호)는 기억시키지 마세요.
  • 메모리 파일이 있는 컴퓨터를 다른 사람과 같이 쓴다면 이 점을 고려하세요.
  • 새 메모리를 원치 않으면 Configure에서 Enable memories를 끕니다. 시크릿 작업(Incognito mode)은 일반 브라우저 프로필 상태 없이 실행되지만, 시크릿 작업에서 메모리가 만들어지는지는 공식 도움말에 설명이 없습니다. 확실히 막으려면 Enable memories를 끄세요.
  • 개인정보 처리 전반은 15장에서 다룹니다.

10.7 Context Awareness

무엇인가

화면 문구는 이렇습니다: "Let Aside remember your day. Aside captures what you do in your browser and apps so agents can recall it later."(Aside가 당신의 하루를 기억하게 하세요. 브라우저와 앱에서 한 활동을 캡처해 두면 에이전트가 나중에 떠올릴 수 있습니다.)

예를 들어 "어제 오후에 보던 견적서 사이트가 어디였지?" 같은 질문에 답하는 데 쓸 수 있습니다. 변경 이력에는 일간 요약(Daily summaries)이 생성된다고 되어 있습니다.

기본값과 지원 환경

  • 기본은 꺼짐입니다. 변경 이력: "모든 계정에서 쓸 수 있지만, 사용자가 켜기 전까지 꺼져 있다."
  • 지원 기기는 Mac과 Windows입니다. Windows에서도 앱 활동을 캡처하고 기존 방문 기록과 함께 검색할 수 있습니다(변경 이력 기준).
  • 요약은 내가 선택한 모델로 만들어집니다. 다른 연결 공급자로 요금이 청구되지 않도록 고쳤다고 변경 이력에 적혀 있습니다.
  • 캡처는 켠 계정을 따르고, 그 계정의 브라우저 프로필 활동만 담습니다. 다른 계정으로 로그인하면 어느 계정이 캡처 중인지 표시되고, Use this account로 옮길 수 있습니다.
  • 플랜: 가장 최근 변경 이력(v1.26.1021)은 "지원되는 Mac과 Windows 기기의 모든 계정에서 쓸 수 있다"고 설명합니다. 그 직전 이력에는 "플랜이 캡처를 막으면 설정 설명에 Max가 필요하다고 표시된다"는 항목이 있으므로, 내 화면에 그런 안내가 보이면 그것을 따르세요.

켜는 법

  1. Settings > Memory > Context Awareness를 엽니다.
  2. Capture 아래의 Enable Context Awareness("Capture your activity on this device.", 이 기기의 활동을 캡처) 스위치를 켭니다.
  3. 운영체제가 권한을 요청하면 안내를 따릅니다. Mac에서는 Input Monitoring(입력 모니터링)과 Screen Recording(화면 기록) 권한이 언급됩니다(변경 이력 기준). 권한은 운영체제의 시스템 설정에서 허용합니다.

켜기 전에 생각할 점

  • 민감한 활동도 기록될 수 있습니다. 은행, 의료, 고객 개인정보, 사내 기밀 문서를 자주 여는 컴퓨터라면 특히 신중하게 정하세요. 무엇을 어떤 형태로 저장하는지는 공식 도움말에 설명이 없습니다.
  • 캡처한 기록은 이 기기에 남고, 다른 기기로 동기화되지 않습니다(공식 도움말: Context Awareness 기록은 각 기기에 남음).
  • 일간 요약을 만들 때 선택한 모델이 쓰이므로 크레딧이 소모될 수 있습니다. 변경 이력에는 백그라운드 사용량이 기능 이름(Context Awareness 요약 등)으로 표시된다고 되어 있습니다. 확인은 Settings > Plan & Usage에서 합니다.
  • 켜 보고 별로면 언제든 같은 화면에서 스위치를 끄면 됩니다. 쌓인 기록은 Settings > Memory에서 볼 수 있습니다. 끈 뒤 이미 만들어진 기록을 지우는 방법은 공식 도움말에 없습니다. [확인 필요]

주의: 공용 컴퓨터, 고객 정보를 다루는 컴퓨터, 회사 보안 정책이 있는 컴퓨터에서는 켜기 전에 규정을 먼저 확인하세요.

팁: 처음에는 하루나 이틀만 켜 보고, 실제로 "어제 본 자료 찾아줘" 같은 요청이 얼마나 도움이 되는지 확인한 뒤 계속 둘지 결정하세요.

11. 루틴: 반복 업무 자동화

이 장에서 할 일: 정해진 때에 Aside가 알아서 일하도록 루틴을 만들고, 결과를 확인하고, 안전하게 운영합니다.

11.1 루틴이란

루틴(Routine)은 매번 손으로 작업을 시작하지 않아도 Aside가 반복되는 일을 대신 실행하게 하는 기능입니다. "매일 아침 9시에 오늘 일정과 중요한 메일을 요약해줘"처럼 일정이 있는 일에 알맞습니다.

11.2 루틴의 종류

종류(공식 도움말) 만들기 창의 Type 동작 어울리는 일
Cron(크론) 루틴 Standalone 정해진 일정마다 새 작업을 시작합니다. 주간 요약처럼 매번 독립적으로 끝나는 반복 작업
Heartbeat(하트비트) 루틴 Runs in task 기존 채팅을 깨워서 이어서 진행합니다. 같은 채팅에서 새 맥락을 더해 가며 계속하는 일

공식 도움말의 이름(Cron, Heartbeat)과 만들기 창 Advanced > Type의 선택지(Standalone, Runs in task)를 이렇게 짝지은 것은 화면 관찰 기준입니다(공식 문서에 명시 없음). 처음에는 Standalone이 쉽습니다. 채팅으로 만든 루틴이 어느 종류인지는 루틴 행의 Edit을 열어 Advanced > Type에서 확인하세요.

11.3 루틴 만드는 법 2가지

방법 1. 채팅에서 말로 부탁하기

가장 쉽습니다. 일정과 할 일을 한 문장씩 분명히 적습니다.

평일 아침 8시 30분마다 오늘 일정과 읽지 않은 중요한 메일을 5줄로 요약해서 알려줘. 메일 답장은 보내지 말고 초안만 준비해줘. 이걸 루틴으로 만들어줘.

매월 1일 오전 9시에 지난달 영수증 메일을 모아서 날짜, 금액, 거래처가 있는 표로 정리해줘. 이걸 루틴으로 만들어줘.

참고: 채팅에서 만든 루틴도 Settings > Routines에 표시됩니다(변경 이력 기준). 실행 횟수가 정해진 루틴은 마지막 실행 뒤 자동으로 멈추고, 1회성 루틴은 끝나면 목록에 Routine completed로 표시됩니다.

11.5 루틴 관리하기

Settings > Routines 목록의 각 행에는 루틴 이름, 일정, 오른쪽 스위치가 있습니다. 행에 마우스를 올리면 ...(Actions) 메뉴가 나타납니다(2026-11-17 화면 기준).

하고 싶은 일 방법
잠시 멈추기 / 다시 시작 행의 스위치를 끕니다/켭니다. 스위치가 켜져 있으면 실행 중, 꺼져 있으면 일시정지 상태입니다. ... 메뉴의 Pause로도 멈출 수 있습니다. 멈춘 루틴에는 멈춘 이유가 표시됩니다(변경 이력 기준).
지금 바로 실행 ... > Run now(변경 이력의 이름은 Trigger now). 일시정지 상태에서는 쓸 수 없습니다.
지난 실행 보기 ... > Run history
지시나 일정 고치기 ... > Edit
삭제 ... > Remove
현재 활성 루틴과 초안 제안 확인 목록에서 확인

팁: 채팅으로도 됩니다. "아침 요약 루틴을 잠시 멈춰줘"라고 요청하면 에이전트가 루틴을 일시정지하거나 재개합니다(변경 이력 기준).

11.6 루틴 추천 받기

Aside가 내 방문 기록과 활동에서 반복되는 일을 찾아 초안 루틴을 제안해 줍니다.

  1. Settings > Routines 목록을 엽니다.
  2. Find routine suggestions(이미 제안이 있으면 Find more suggestions)를 선택합니다. 이 버튼 이름은 공식 도움말 기준이며, 2026-11-17 화면 수집 때는 확인하지 못했습니다.
  3. 제안된 초안을 읽고, 지시 내용, 일정, 대상 채팅을 필요하면 고칩니다.
  4. 쓰려면 Activate(활성화), 필요 없으면 Dismiss(무시)를 누릅니다.

주의: 제안은 내가 Activate를 누르기 전에는 실행되지 않는 초안입니다. 하지만 활성화한 뒤에는 정해진 일정에 계속 실행되니 지시 내용을 꼭 읽고 고치세요.

11.7 결과 확인하는 곳

  • 채팅 목록 카드. 루틴이 만든 채팅에는 일정 배지(예: Everyday 9PM)가 붙습니다. 새 탭의 Chats와 채팅 목록(All Chats)에서 확인합니다.
  • 새 탭의 Routines 탭. 새 탭 아래쪽 Chats, Routines 중 Routines를 누르면 루틴 카드가 보입니다. 확인하지 않은 항목은 읽지 않음 표시가 붙습니다(변경 이력 기준).
  • 알림. 루틴마다 만들기 창의 Notifications 스위치(기본 켜짐)로 알림을 켜고 끕니다. 알림 범위와 소리는 Settings > Agents의 Task notifications, Completion sound도 함께 확인하세요(13장).
  • 실행 기록. 루틴 행의 ... > Run history에서 지난 실행을 봅니다. Standalone 루틴의 실행 결과는 해당 채팅에 남습니다(변경 이력 기준). 결과를 읽고 후속 요청으로 이어서 고칠 수 있습니다.

11.9 좋은 루틴 예시 5가지

예시는 일반적인 업무 상황입니다. 그대로 복사해 내 상황에 맞게 고치세요. 외부에 글을 올리거나 메일을 보내는 일은 자동으로 하지 말고 내 승인을 받은 뒤에만 하도록 적었습니다.

1. 아침 브리핑 (직장인)

평일 아침 8시 30분에 오늘 캘린더 일정과 읽지 않은 중요한 메일을 5줄로 요약해줘. 답장이 필요한 메일은 초안만 만들고 절대 보내지 마. 결과는 이 채팅에 남겨줘.

2. 영수증 월간 정리 (1인 사업자)

매월 1일 오전 9시에 지난달 받은 영수증, 결제 알림 메일을 모아서 날짜, 금액, 거래처, 용도 후보를 표로 정리해줘. 판단이 애매한 항목은 "확인 필요"로 표시하고, 스프레드시트에 쓰기 전에 나에게 먼저 보여줘.

3. 블로그 소재 주간 발굴

매주 월요일 오전 10시에 내 업종 관련 최신 뉴스와 자주 나오는 질문을 조사해서, 이번 주 블로그 소재 후보 5개를 제목, 핵심 근거, 예상 독자와 함께 정리해줘. 글을 직접 올리거나 발행하지는 마. 결과만 보여줘.

4. 경쟁사와 가격 모니터링

매주 금요일 오후 5시에 내가 정한 경쟁사 3곳의 웹사이트에서 가격과 새 공지를 확인해서, 지난주와 달라진 점만 요약해줘. 바뀐 게 없으면 "변동 없음"이라고만 해줘. 로그인이나 주문은 하지 마.

5. 주간 회고 (퇴근 전)

매주 금요일 오후 6시에 이번 주 내가 Aside로 한 작업을 훑어보고, 잘 된 점, 막힌 점, 다음 주에 스킬이나 메모리로 남길 만한 반복 작업 후보를 정리해줘.

팁: 5번 같은 회고 루틴은 9장의 스킬 후보를 찾는 데 도움이 됩니다. 반복해서 나오는 일은 스킬로 만들고, 시간에 묶인 일은 루틴으로 돌리세요.

11.10 운영 원칙

  1. 처음 며칠은 결과를 꼭 읽습니다. 지시가 어긋나 있으면 이때 고칩니다.
  2. 결과를 읽지 않는 루틴은 정지하거나 삭제합니다. 쓰이지 않는 루틴은 크레딧만 쓰고 혼란을 만듭니다.
  3. 외부로 나가는 일(게시, 발송, 결제)은 승인 후에만 하도록 지시에 적습니다. 권한 설정은 13장을 보세요.
  4. 일정은 너무 촘촘하게 잡지 않습니다. 짧은 간격(예: 10분마다)은 겹침과 크레딧 소모가 늘 수 있습니다. 필요한 만큼만 돌립니다.
  5. 한 번은 Run now로 시험합니다. 일정을 기다리지 않고 바로 결과를 확인합니다.
  6. 크레딧을 확인합니다. 루틴의 사용 내역은 Settings > Plan & Usage의 사용 내역에서 볼 수 있습니다. 요금과 크레딧은 18장을 보세요.
  7. 컴퓨터가 켜져 있어야 합니다. 중요한 루틴은 실행 시각에 컴퓨터가 깨어 있는지 확인하세요.

12.2 제공자 연결하기

  1. Settings > Models를 엽니다.
  2. Providers 영역에서 Connect를 누릅니다.
  3. 창에서 Subscription, API, Local 중 하나를 고르고 제공자를 선택합니다.
  4. Subscription은 열린 로그인 창에서 로그인을 끝내고 Aside로 돌아옵니다. API는 키를 붙여 넣습니다.
  5. 연결되면 Providers 목록과 입력창의 모델 메뉴에 나타납니다. 지원하는 구독 제공자는 사용량 표시도 보입니다.

설치 뒤 Claude를 추가로 연결하기 (Windows 예)

첫 설정에서 ChatGPT만 연결했다면 Claude는 나중에 더할 수 있습니다. 선택 단계이므로 ChatGPT만 쓴다면 건너뛰어도 됩니다.

  1. 왼쪽 위 계정 아이콘 → Settings → Models로 이동합니다.
  2. Providers의 Connect를 눌러 Claude를 고르고, 열린 창에서 Claude 계정 로그인·인증을 마칩니다.
  3. 연결되면 입력창의 모델 메뉴에서 Claude 모델을 고를 수 있습니다.

Claude 행에 Reauthentication required(다시 인증 필요)가 보이면 연결이 끊긴 상태입니다. 오른쪽 ... 메뉴에서 다시 연결하거나 Connect로 다시 로그인하세요.

12.3 로컬 모델 연결 5단계

인터넷 없이, 또는 내 컴퓨터 안에서만 모델을 돌리고 싶을 때 씁니다. Claude나 OpenAI 계정이 없어도 됩니다.

  1. Ollama 또는 LM Studio를 설치하고, 도구 호출(tool calling)을 지원하는 모델을 내려받은 뒤 로컬 서버를 켭니다.
  2. Settings > Models > Providers > Connect에서 Local 아래의 Ollama 또는 LM Studio를 고릅니다.
  3. 서버가 같은 컴퓨터에서 돌면 Base URL은 기본값을 그대로 둡니다. API Key는 서버가 요구할 때만 입력합니다.
  4. Select models에서 모델을 고르고 Connect를 누릅니다.
  5. 작업의 모델 메뉴에서 그 모델을 고르거나, Settings > Models > Task models에서 기본값으로 지정합니다.

주의: 로컬 서버는 Aside가 모델을 쓰는 동안 계속 켜져 있어야 합니다. 어떤 작업까지 해낼 수 있는지는 모델 성능과 내 컴퓨터 사양에 달려 있습니다.

  3. 고른 모델은 지금 보내는 작업에 쓰이고, 마지막에 쓴 모델이 다음 새 채팅의 기본값이 됩니다.

12.6 모델 고르는 요령

공식 도움말에 "이럴 땐 이 모델"이라는 추천표는 없습니다. 아래는 Task models 항목의 설명에서 끌어낸 실용 기준입니다.

상황 방향
짧은 요약, 간단한 정리 가볍고 빠른 모델(Fast 성격)

13. 권한과 안전장치

이 장에서 할 일: 에이전트가 파일과 도구를 어디까지 쓸 수 있는지 정하고, 민감한 행동 앞에서 멈추게 하는 방법을 익힙니다.

에이전트(AI 일꾼)는 읽고, 쓰고, 탐색하고, 명령을 실행할 수 있습니다. 권한 설정은 그 범위를 정하는 안전장치입니다.

13.1 권한 모드 3가지

새 작업마다 권한 모드가 있습니다.

모드 설명
Read only 브라우저와 파일 내용을 살펴보기만 합니다. 내 파일을 바꾸지 않습니다.
Guard 승인한 폴더 안에서 일하고, 그 밖의 폴더에 접근하기 전에는 물어봅니다. 새 작업의 기본값입니다.
Full access 컴퓨터 어디든 읽고 쓸 수 있습니다.

주의: Full access는 파일 접근 범위만 넓힙니다. 저장된 비밀번호 값은 Full access에서도 여전히 AI에게 보이지 않습니다(14장).

처음에는 Guard로 시작하고, 꼭 필요할 때만 Full access를 쓰는 것을 권합니다.

13.2 권한 모드 바꾸는 곳

이번 작업만 바꾸기

  1. 입력창 왼쪽의 +(Composer options)를 누릅니다.
  2. Permission에 마우스를 올려 Read only, Guard, Full access 중 하나를 고릅니다.

모든 새 작업의 기본값 바꾸기

  • Settings > Agents > Access permission에서 바꿉니다. 같은 Permission 메뉴 맨 아래 Global setting 링크로도 이동할 수 있습니다.
  • 새 작업의 기본값은 Guard입니다(공식 도움말). 이 장의 그림에 Full access가 보이는 것은 캡처한 계정에서 기본값을 바꿔 두었기 때문입니다. 내 설정값을 한 번 확인해 보세요.

Disable command sandbox: Permission 메뉴의 이 항목은 이번 작업에서 명령 실행 샌드박스를 끕니다. 전체 권한이 필요한 작업은 샌드박스를 끄기 전에 확인을 요청하고, 취소하면 권한이 그대로 유지됩니다. 선택은 그 작업에만 적용됩니다.

참고: 입력창에는 Ask first / Skip confirmation을 고르는 메뉴도 있습니다. 이름으로 보아 확인을 먼저 받을지 건너뛸지 정하는 메뉴로 보이지만, 공식 도움말에 설명이 없습니다(화면 관찰 기준).

13.3 Settings > Agents 의 권한 영역

Settings > Agents를 아래로 내리면 권한 섹션이 있습니다.

Sandbox

Enable sandbox를 켜 두면 명령이 OS 수준의 격리 환경에서 실행되어, 작업이 내가 허용한 파일과 폴더로 제한됩니다.

File permissions(파일 권한)

목록 의미
Can view 이 폴더의 파일을 볼 수 있습니다. 아래 Can edit에도 넣지 않으면 고칠 수 없습니다.
Can edit 이 폴더에서 파일을 만들고, 고치고, 지울 수 있습니다. 목록은 작게 유지하세요.

목록에는 Project root(프로젝트 폴더), Default(기본 폴더) 항목이 표시되고, Add로 폴더를 더합니다.

Tool permissions(도구 권한)

값 동작
Allow 확인 없이 실행합니다.
Ask 실행 전에 물어봅니다.
Deny 실행 전에 거부합니다.

각 값 아래 Add Rule로 규칙을 더합니다. Deny가 Ask와 Allow보다 우선합니다.

13.4 에이전트 수준 규칙과 작업 수준 규칙

  • 에이전트 수준 권한: Settings > Agents에 있고, 모든 작업의 기본값입니다.
  • 작업 수준 권한: 각 작업의 입력창(+ > Permission)에서 정합니다.
  • 작업에 자체 권한 설정이 있으면, 에이전트 기본값 위에 그 작업의 설정이 덧씌워집니다.

13.5 승인 흐름: 민감한 행동은 확인을 기다립니다

로그인은 Aside Vault가 해 주더라도, 결제, 게시, 메시지 보내기 같은 민감한 행동은 작업이 승인을 요청하면 내 확인을 기다립니다. 반대로 다음과 같이 지시문에 멈출 지점을 적어 두면 더 안전합니다.

고객 지원 대시보드에 로그인해서 열려 있는 문의를 검토하고 답장 초안을 써 주세요. 게시하기 전에 반드시 멈추고 내 확인을 받으세요.

사이트가 2단계 인증, 패스키 승인, CAPTCHA, 본인 확인을 요구하면 화면에 보이는 단계를 직접 마친 뒤 작업을 이어 가게 하세요.

  3. 작업을 이 컴퓨터에서 실행합니다.
  • macOS와 Windows에서 작동합니다.

14. 비밀번호 관리자: Aside Vault

이 장에서 할 일: Aside Vault를 처음 설정하고, 기존 비밀번호를 가져오고, AI가 로그인에 쓸 수 있는 범위를 정합니다.

14.1 Aside Vault란

Aside Vault는 Aside에 내장된 비밀번호 관리자입니다. 핵심은 한 가지입니다. 에이전트는 비밀번호 원문을 받지 않고, 로그인이라는 동작만 사용합니다. 그래서 급여 도구, 대시보드, 메일, 고객관리 시스템(CRM), 결제 내역 페이지처럼 로그인 뒤에 있는 일도 맡길 수 있습니다.

기능

  • 웹사이트 로그인 정보 저장
  • 로그인 화면에서 맞는 계정 제안
  • AI에게 보여 주지 않고 비밀번호 자동 입력
  • 사이트가 요구하면 패스키, FIDO2, TOTP(일회용 인증 코드) 입력 지원
  • 에이전트가 저장된 로그인 정보를 쓸 수 있는 시점 제어

에이전트가 로그인하는 방식: 작업이 로그인 페이지에 닿으면 Aside가 대상 URL과 내 접근 정책을 확인합니다. 맞는 정보가 허용되어 있으면 자동 입력합니다. 2단계 인증, 패스키 승인, CAPTCHA, 본인 확인이 나오면 화면의 단계를 직접 마친 뒤 작업을 이어 가세요.

14.2 처음 설정 7단계

  1. Settings > Passwords를 엽니다. Aside Vault is locked(Vault가 잠김)가 보이면 Unlock으로 먼저 잠금을 푸세요. 화면 안내대로 Vault를 풀어야 세부 설정을 바꿀 수 있습니다.
  2. 기본 비밀번호 관리자를 고릅니다. Aside가 비밀번호를 관리하게 하려면 Use default password manager를 켭니다.
  3. Autofill(자동 입력)을 켭니다. 기본은 켜짐입니다.
  4. URL 일치 방식을 고릅니다.
  5. Aside가 채우지 말아야 할 사이트는 Excluded domains에 추가합니다.
  6. 보안이 약한 프로토콜(http)에서 제안을 보일지 정합니다.
  7. 시크릿 창에서 자동 입력을 쓸지 정합니다.

참고: google.com, youtube.com, gmail.com처럼 같은 계정을 쓰는 흔한 도메인은 기본적으로 같은 곳으로 취급합니다. 설정이 끝나면 로그인 제안, 저장 안내, 생성 비밀번호 제안, 패스키와 FIDO2 창, TOTP 입력 안내가 나타납니다. 3번부터 7번까지의 항목 이름은 공식 도움말 기준입니다. 그림 14-3은 Vault가 잠긴 상태라 이 항목들이 보이지 않습니다.

14.3 다른 곳의 비밀번호 가져오기

Settings > Passwords > Import에서 가져옵니다.

지원하는 소스: 1Password, Apple Passwords, Bitwarden, Chrome, Dashlane, Edge, Firefox, LastPass(CSV), 일반 CSV

  1. 원래 비밀번호 관리자에서 비밀번호를 내보냅니다(export).
  2. Aside의 비밀번호 설정을 엽니다.
  3. Import를 누릅니다.
  4. 소스를 고릅니다.
  5. 내보낸 파일을 고릅니다. 소스별로 안내 화면이 더 나오면 따릅니다.
  6. 가져오기 결과를 확인합니다.

일반 CSV는 다음 열이 있어야 합니다.

name,url,username,password

주의: 내보낸 파일에는 비밀번호가 그대로 들어 있습니다. 가져온 뒤에는 백업이 정말 필요한 경우가 아니면 파일을 지우세요.

14.4 AI 접근 정책

Settings > Passwords > Access policy for AI agents에서 에이전트가 저장된 로그인 정보를 쓸 수 있는 때를 정합니다.

정책 의미
Always allow 항상 허용합니다. 기본값입니다.
While unlocked Vault가 잠금 해제된 동안에만 허용합니다.
Never 허용하지 않습니다.
  • 가져온 항목은 항목별로 전체 정책을 덮어쓸 수 있습니다.
  • 시크릿(Incognito) 작업에서는 비밀번호 관리자 접근을 쓸 수 없습니다.
  • 로그인 항목은 자동 입력을 만들기 전에 대상 URL을 확인합니다. 맞는 항목을 찾을 때도 비밀번호는 에이전트에게 드러나지 않습니다.

14.5 Touch ID와 Windows Hello

Mac의 Touch ID, Windows의 Windows Hello로 Vault를 풀 수 있습니다. 지원 기기에서 처음 Vault를 열 때, 아직 등록하지 않았다면 안내가 나옵니다.

  • Enable: 등록합니다. 다음부터 잠금 해제는 기기 인증으로 합니다.
  • Not now: 닫습니다. 다시 묻지 않지만 나중에 Settings > Passwords에서 켤 수 있습니다.

이 기능은 푸는 방법만 바꿉니다. 열린 뒤 에이전트가 할 수 있는 일은 14.4의 접근 정책이 그대로 정합니다.

참고: Vault 비밀번호는 Aside 계정 비밀번호와 별개입니다.

14.6 Vault가 잠금 해제되지 않을 때

잠금 화면(도구 모음의 열쇠 아이콘 또는 Settings > Passwords)에서 Forgot password?를 누릅니다.

상황 방법
복구 키가 있다 12단어 복구 키를 입력하고 새 잠금 해제 비밀번호를 정합니다. 저장한 비밀번호는 그대로입니다. 복구 키는 이름이 aside-recovery-key로 시작하는 .txt 파일이나 Vault를 설정할 때 쓴 이메일에서 찾습니다.
복구 키가 없다 Reset Aside Vault를 고릅니다. 빈 Vault가 새로 만들어지고, 예전 Vault의 비밀번호는 복구할 수 없습니다.

초기화 과정: reset my vault 입력, 이메일 코드 입력, 새 비밀번호 설정, 새 복구 키 저장과 확인, 마지막에 Reset. 마지막 단계 전에 창을 닫으면 아무것도 바뀌지 않으므로, 새 비밀번호와 키도 쓸 수 없습니다. 초기화 뒤에도 거부되면 초기화한 계정과 같은 계정으로 풀고 있는지 확인하세요. Settings > Passwords에 이 기기의 계정과 Vault 목록이 있습니다.

팁: 복구 키 파일은 비밀번호 관리자나 안전한 곳에 따로 보관하세요. 12단어가 없으면 초기화밖에 방법이 없습니다.

14.7 외부 비밀번호 관리자 연결

이미 다른 비밀번호 관리자를 쓰고 있다면 Settings > Passwords의 Connect external password manager(외부 비밀번호 관리자 연결)를 확인하세요. 이 항목의 연결 절차와 지원 목록은 공식 도움말에 설명이 없습니다. 참고로 2026-11-17 스킬 목록의 Password Manager 묶음에는 Apple Passwords, Bitwarden, Password Manager(Aside Vault) 스킬이 있습니다(9장).

  • 1Password 확장 프로그램이 동작하지 않을 때는 19장을 보세요.
  • Apple Passwords 확장이 동작하지 않을 때는 Aside에 Apple Passwords 스킬로 연결 상태를 점검해 줘라고 지시하면 점검해 줍니다(공식 도움말은 영어 문장으로 안내).

14.8 동기화와 Vault 초기화

  • Vault 데이터는 암호화한 뒤 동기화되고, 저장된 비밀번호 값은 AI에게 보이지 않습니다.
  • Settings > Passwords에는 Vault 관리, 클라우드 동기화, 가져오기, 내보내기, 지우기가 있습니다.
  • Clear vault data는 로컬 항목, Vault 키, Vault를 지우고 새 Personal Vault를 만든 뒤 초기화 상태를 동기화합니다.

주의: Clear vault data 전에는 반드시 비밀번호를 내보내기 해서 백업하세요. 지우면 되돌릴 수 없습니다. 내보낸 파일은 보관이 끝나면 지우세요.

Vault 복구 키는 브라우저 데이터 복구(Settings > Account > Browser data recovery)와 따로 관리됩니다. 2026년 9월 이전에 만든 계정은 같은 12단어 키가 브라우저 동기화 복구에도 쓰이므로, 복구 키를 바꿀 때 "브라우저 동기화를 먼저 복원하라"는 안내가 나올 수 있습니다. 자세한 내용은 19장을 보세요.

15.4 시크릿 작업

입력창 + 메뉴의 Incognito mode를 체크하면 시크릿 작업이 됩니다. 시크릿 작업은 일반 브라우저 프로필 상태(로그인된 쿠키 등) 없이 실행되고, Aside Vault 접근도 쓸 수 없습니다(14.4). 시크릿 작업이 채팅 기록과 메모리에 어떻게 남는지는 공식 도움말에 설명이 없습니다. [확인 필요]

15.5 메모리와 Context Awareness 끄기

Aside가 나의 하루를 기억하게 하는 기능은 켜고 끌 수 있습니다. 메모리는 Settings > Memory > Configure의 Enable memories, Context Awareness는 Settings > Memory > Context Awareness의 Enable Context Awareness에서 조절합니다. Context Awareness는 이 기기에서 브라우저와 앱 활동을 기록하는 기능입니다. 자세한 설명과 보관 기간 설정은 10장을 보세요.

16. 채널: 메신저로 Aside 부리기

이 장에서 할 일: 내가 만든 봇을 Slack, Telegram, Discord에 연결해, 메신저 메시지로 Aside에 작업을 시키고 같은 대화창에서 결과를 받습니다.

16.1 채널이란

채널(Channels)은 내가 소유한 봇을 Aside와 이어 주는 기능입니다. 메신저에서 봇에게 메시지를 보내면, Aside가 그 요청을 브라우저 작업으로 실행하고 같은 스레드(대화 묶음)에 답을 올립니다. 자리를 비웠을 때 휴대폰에서 작업을 시키거나, 팀원이 쓰는 챗봇을 만들 때 쓸 수 있습니다.

핵심 원리는 다음과 같습니다.

  • 사용자가 플랫폼에서 봇을 만들고, 그 자격 증명(토큰 등)을 Aside에 등록합니다.
  • Aside는 내 컴퓨터에서 플랫폼에 접속합니다. 따라서 작업은 내 컴퓨터에서 실행되며, Aside가 켜져 있는 동안에만 봇이 응답합니다.
  • 대화 하나는 Aside 작업 하나에 대응합니다. 같은 스레드에서 이어 보내는 메시지는 그 작업을 이어 갑니다.
  • 자격 증명은 일반 파일이 아니라 운영체제 보안 저장소에 저장됩니다.
  • 같은 플랫폼에 봇을 여러 개 연결할 수 있습니다. 봇마다 Add를 누릅니다.

주의: 컴퓨터가 잠자기 상태가 되거나 꺼지면 채널 봇도 멈춥니다. 18장의 "여러 기기" 절을 함께 읽어 보세요.

참고: 화면 기준(2026-11-17)으로 Settings > Channels(설정 > 채널) 제목은 "Aside, Anywhere"이고, 설명은 "Slack, Discord, Telegram으로 Aside를 원격 조작하거나 팀용 챗봇을 만들 수 있다"는 취지입니다. 플랜 조건은 도움말에 없고, 공식 변경 이력(v1.26.818.1059, 2026-08-18)에 "Slack과 Telegram 원격 조작을 Pro에 열고, Free에서는 개요와 업그레이드 안내를 보여 준다"는 기록이 있습니다. 지금 쓰는 플랜에서 연결할 수 있는지는 Settings > Channels 화면에서 확인하세요.

16.2 연결 설정하기

  1. Settings > Channels를 엽니다.
  2. 연결할 플랫폼(Slack, Telegram, Discord)을 고르고 설정 방식을 선택합니다.
    • Create with Aside: Aside가 작업을 시작해 봇을 만들고 자격 증명 등록까지 대신해 줍니다.
    • Manual: 자격 증명 입력란이 나타나고, 직접 채웁니다.
  3. 플랫폼별 봇 만들기 안내를 따릅니다: Create a Slack bot, Create a Telegram bot, Create a Discord bot.
  4. 채널 화면에서 연결 상태가 연결됨(connected)으로 표시되는지 확인합니다.

팁: Create with Aside는 플랫폼에서 내 사용자 ID를 확인할 수 있으면 설정 중에 내 계정을 자동으로 페어링합니다. Manual 연결이나 ID를 알려 주지 않는 플랫폼은 아래 16.3의 페어링 절차를 거칩니다.

연결 목록에서는 연결을 켜기, 끄기, 다시 시작하기, 삭제하기를 할 수 있습니다. 연결을 삭제하면 저장된 자격 증명도 함께 지워집니다.

16.3 누가 봇을 쓸 수 있나: 접근 권한과 페어링

봇을 찾아낸 사람은 누구나 메시지를 보낼 수 있으므로, Aside는 "누구의 지시를 받을지"를 따로 정합니다. 연결의 Options 탭에서 Access permission(접근 권한)을 고릅니다.

선택지 의미 권장
Only me (기본값) 페어링된 한 사람(나)만 DM과 그룹에서 봇을 쓸 수 있습니다. 다른 사람이 요청해도 작업은 시작되지 않습니다. 개인 사용
Paired people only 내가 승인한 사람만 쓸 수 있습니다. 팀 사용
Everyone 페어링하지 않은 사람도 쓸 수 있습니다. 가급적 피하기

주의: Everyone은 봇을 찾은 누구나 내 컴퓨터에서 작업을 실행시킬 수 있다는 뜻입니다. 내 파일과 로그인된 사이트가 걸려 있으므로 특별한 이유가 없으면 선택하지 마세요. 이미 만든 연결은 저장된 접근 설정을 그대로 유지합니다.

페어링 승인하기

  1. 연결 설정에서 Pairing 탭을 엽니다.
  2. 대기 중인 요청을 찾아 Approve(승인)를 누릅니다. 거절하거나, 이미 승인한 사람 목록을 확인할 수도 있습니다.

페어링 요청은 1시간 뒤 만료됩니다. DM과 그룹 메시지 모두 해당됩니다. 승인 권한은 요청을 처리하는 시점에 사람마다 다시 확인됩니다.

여러 사람을 쓰게 하려면 먼저 Access permission을 Paired people only로 바꿔야 합니다. Only me 상태에서 내가 페어링된 뒤에는 다른 사람이 요청해도 거부됩니다.

16.4 봇과 대화하는 법

  • DM(1:1 메시지): 보내는 모든 메시지가 봇에게 전달됩니다.
  • 공유 채널: 봇을 멘션(@)해서 대화를 시작합니다. 그 스레드에서 이어지는 답장은 다시 멘션하지 않아도 같은 대화로 이어집니다.
  • 이미 있는 스레드에 봇 부르기: 스레드 안에서 봇을 한 번 멘션하면 그 스레드가 새 대화로 시작됩니다. 이후에는 멘션 없이 이어집니다.
  • Require mentions in threads(스레드에서 멘션 필요): 기본은 켜짐입니다. 끄면 멘션 없는 첫 스레드(또는 토픽) 메시지만으로도 봇이 시작됩니다. 이때 그 스레드에서 페어링된 사람이 먼저 쓴 메시지가 맥락으로 전달됩니다.
  • 첨부 파일: 20MB까지 작업으로 전달됩니다.

16.7 연결 설정 화면: 세 개의 탭

채널 목록에서 연결을 열면 설정이 세 탭으로 나뉩니다.

탭 내용
Options Access permission(기본 Only me), Require mentions in threads(기본 켜짐), New messages during a task(기본 Queue)
Pairing 대기 중인 페어링 요청 승인 또는 거절, 승인된 사람 확인
Credentials 저장된 토큰 갱신, 연결을 프로젝트에 묶기

Credentials 탭에서 연결을 프로젝트에 묶으면, 이 채널에서 시작한 작업이 그 프로젝트의 작업 공간과 메모리를 함께 씁니다. 프로젝트는 8장에서 설명합니다. 묶지 않으면 프로젝트 없이 실행됩니다.

16.8 다른 봇이 보낸 메시지

Slack, Discord, Telegram에서 다른 봇이 보낸 메시지는 사람과 같은 접근 규칙과 멘션 규칙을 따릅니다.

  • 기존 Pairing 탭에서 그 봇의 요청을 승인하거나, Everyone을 선택해 페어링 없이 허용할 수 있습니다.
  • Aside는 자기 자신이 보낸 메시지는 무시합니다. 봇에게 페어링 관리 권한을 자동으로 주지도 않습니다.
  • Telegram은 추가로 BotFather에서 "Bot-to-Bot Communication Mode"를 켜야 합니다. 개인 대화는 양쪽 봇 모두, 그룹에서는 명령 멘션(/command@봇이름)이나 직접 답장을 위해 적어도 한쪽이 켜야 합니다. 그룹의 일반 봇 메시지를 받으려면 받는 봇이 이 모드를 켜고, 그룹 관리자이거나 Group Privacy Mode가 꺼져 있어야 합니다.

16.9 Personal Assistants (PRO)

Settings > Channels 아래쪽의 Personal Assistants에는 PRO 표시가 붙어 있고, 화면에 Grok Bot(SpaceXAI), dots(OpenAI), Muse(Meta)가 나열됩니다(2026-11-17 화면 기준). 이 기능은 앞의 메신저 봇과 방향이 반대입니다. 외부 AI 비서가 Aside를 도구로 불러서 내 컴퓨터의 브라우저 작업을 시키는 방식입니다.

세 비서의 공통 준비 사항은 다음과 같습니다.

  • Pro 플랜이 필요합니다.
  • Settings > Developers에서 Remote Control을 켭니다(17.8 참고). 비서가 이 기능을 통해 내 브라우저에 닿습니다.
  • 비서가 쓰는 동안 내 컴퓨터에서 Aside가 실행 중이어야 합니다.
  • 해당 비서 서비스의 계정이 필요합니다(Grok 계정, ChatGPT 계정, Muse 계정).
  • 비서가 api.aside.com에 접근하도록 허용해야 합니다. 비서 쪽 네트워크 정책 때문에 막히면 Aside가 풀어 줄 수 없습니다.

공통 연결 흐름은 다음과 같습니다.

  1. Aside가 채워 주는 "연결 프롬프트"(내 Aside 이메일과 이 기기의 호스트 이름이 들어간 안내문)를 비서에게 보냅니다.
  2. 비서는 자기 컴퓨터에 Aside CLI를 설치하고 aside login을 실행해, 8자리 로그인 코드와 기기 이름을 알려 줍니다.
  3. 사용자가 Settings > Account의 기기 요청에서 그 코드를 승인합니다(코드는 표시 후 10분 뒤 만료). 비서 화면에 Signed in as <내 이메일>이 보이면 로그인이 끝난 것입니다.
  4. 비서가 aside host list로 내 기기가 online인지 확인하고, aside host use로 기본 호스트로 정합니다.
  5. 이후 비서는 aside exec --host ... "지시문" 형태로 내 컴퓨터에 작업을 보냅니다.
비서 무엇인가 연결 시 특징
Grok Bot Grok 계정의 비서 비서 컴퓨터의 /workspace/.aside/ 아래에 CLI를 설치하도록 안내합니다. 프롬프트를 받은 뒤 Signed in as가 나올 때까지 기다리게 합니다.
dots OpenAI의 비서(ChatGPT 계정 필요). OpenAI 컴퓨터에서 실행됩니다. 연결 프롬프트에 설치, 로그인, 기기 확인, 테스트 작업(예: 페이지 제목 읽기)까지 들어 있습니다. dots의 네트워크 정책이 api.aside.com을 막으면 연결을 중단해야 합니다.
Muse 자체 컴퓨터에서 실행되는 비서(Muse 계정 필요) 비서 컴퓨터의 /home/hatch/.aside/ 아래에 CLI를 설치하도록 안내합니다. 로그인 코드가 틀리면 비서에게 aside login을 다시 실행시키고 새 코드를 씁니다.

팁: 연결 프롬프트에 들어가는 {email}과 {host}는 설정 화면이 알아서 채워 줍니다. 공식 도움말은 Aside의 에이전트가 연결을 대신 진행하는 방식도 설명하는데, 사용자가 직접 할 때는 프롬프트를 복사해 비서에게 붙여넣으면 됩니다.

문제가 생겼을 때 자주 보는 증상은 다음과 같습니다.

증상 원인과 조치
aside host list에서 내 기기가 disabled Settings > Developers에서 Remote Control이 꺼져 있습니다. 켜세요.
aside host list에서 offline 내 컴퓨터에서 Aside가 실행 중이 아닙니다.
비서가 내 컴퓨터가 아니라 자기 컴퓨터에서 작업을 실행 --host 옵션을 빼먹은 것입니다. 호스트 이름을 다시 알려 주세요.
로그인 코드가 거부됨 코드가 만료되었거나 오타입니다. 비서에게 aside login을 다시 시키고 새 코드를 쓰세요.
요청이 Settings > Account에 안 보임 비서가 아직 로그인을 시작하지 않았거나 다른 이메일로 시도했을 수 있습니다. 이미 승인된 로그인은 대기 목록에 남지 않으므로, 다시 시도하기 전에 비서 화면에 Signed in as가 떠 있는지 먼저 확인하세요.
비서가 다시 로그인하라고 함 새 셸은 이전 셸의 환경 변수를 물려받지 않습니다. 같은 ASIDE_CLI_AUTH_PATH를 쓰는지 확인하세요.

주의: 로그인 승인은 방금 비서가 알려 준 코드와 기기 이름이 일치하는 요청 하나만 하세요. 모르는 요청이나 추측한 코드는 승인하지 않습니다. 상세한 로그인 절차는 17.3을 참고하세요.

17. 개발자 도구: CLI, MCP, REPL, Remote Control

이 장에서 할 일: 터미널과 다른 AI 도구에서 Aside를 부르는 방법(CLI, MCP, REPL)과, 다른 기기에서 이 컴퓨터로 작업을 보내는 Remote Control을 설정합니다.

17.1 누구를 위한 장인가

이 장은 터미널(명령 입력 창)을 쓸 수 있는 분을 위한 장입니다. 일반적인 브라우저 사용에는 필요하지 않으니, 필요할 때만 읽으세요. 이런 경우에 씁니다.

  • Codex나 Claude Code 같은 코딩 도구에서 Aside의 브라우저 조작 기능을 쓰고 싶을 때
  • 터미널에서 aside "..."로 브라우저 작업을 시키고 싶을 때
  • 다른 기기나 외부 AI 비서에서 내 컴퓨터의 Aside로 작업을 보내고 싶을 때(Remote Control)

용어를 먼저 풀면 다음과 같습니다.

용어 뜻
CLI 명령줄 도구. 터미널에서 aside라고 입력해 쓰는 프로그램
MCP 다른 AI 도구가 Aside 같은 프로그램을 불러 쓰게 해 주는 표준 연결 방식(Model Context Protocol)
REPL 한 줄씩 명령을 넣어 브라우저를 직접 조작하는 대화형 실행 환경
Remote Control 다른 기기에서 이 컴퓨터의 Aside로 작업을 보내는 기능(PRO)

17.2 CLI 설치와 업데이트

macOS: 터미널에서 다음 명령을 실행합니다.

curl -fsSL https://releases.aside.com/install.sh | bash

Windows: PowerShell을 열고, 서명된 설치 스크립트를 내려받아 게시자와 타임스탬프 서명을 확인한 뒤 실행합니다. 서명 검증에 실패하면 설치가 중단됩니다.

$ErrorActionPreference = 'Stop'
$ProgressPreference = 'SilentlyContinue'
$installer = Join-Path $env:TEMP 'aside-install.ps1'
$publisher = 'CN=AT YOUR SIDE INC, O=AT YOUR SIDE INC, L=San Francisco, S=California, C=US'
Invoke-WebRequest -UseBasicParsing -Uri https://releases.aside.com/install.ps1 -OutFile $installer
$signature = Get-AuthenticodeSignature -LiteralPath $installer
if ($signature.Status -ne 'Valid' -or $null -eq $signature.SignerCertificate -or $signature.SignerCertificate.Subject -ne $publisher -or $null -eq $signature.TimeStamperCertificate) {
  throw "Aside CLI installer signature verification failed ($($signature.Status): $($signature.StatusMessage))."
}
& $installer

Windows 설치 프로그램은 사용자 PATH에 Aside를 추가하므로, aside가 바로 인식되지 않으면 터미널을 새로 여세요. 관리되는 PC에서 서명 검증이 UnknownError로 실패하면, 관리자에게 Microsoft Identity Verification Root Certificate Authority 2020 인증서를 신뢰할 수 있는 루트 인증 기관(Trusted Root Certification Authorities) 저장소에 추가해 달라고 요청하세요.

터미널 대신 화면으로도 설치할 수 있습니다. Settings > Developers의 Aside CLI 항목에서 Install을 누르면 설치, 업데이트, 재설치가 됩니다.

업데이트 확인은 터미널에서 다음 명령입니다.

aside --update

17.3 다른 컴퓨터에서 로그인하기

Aside가 설치된 내 컴퓨터가 아니라, 다른 컴퓨터(서버나 외부 비서의 환경 등)에서 CLI를 로그인할 때의 절차입니다.

  1. 먼저 ASIDE_CLI_AUTH_PATH를 정합니다. 폴더가 아니라 파일 경로여야 하고, 그 컴퓨터에서 쓰기가 허용되며 이후에도 계속 남아 있는 비공개 위치의 절대 경로여야 합니다. 상위 폴더가 있고 쓰기 가능한지 확인하세요($HOME이 쓰기 가능하다고 가정하지 마세요). aside login을 실행하기 전에 설정해야 합니다. 아래 예시의 경로와 이메일은 실제 값으로 바꾸세요.

    export ASIDE_CLI_AUTH_PATH="/your/allowed/private/path/aside-auth.json"
aside login --email "you@example.com"

    PowerShell에서는 $env:ASIDE_CLI_AUTH_PATH = 'C:\your\allowed\private\path\aside-auth.json'로 먼저 설정합니다.

  2. 로그인 명령을 실행한 채로 둡니다. 화면에 8자리 코드와 기기 이름이 나옵니다.

  3. 내 Aside의 Settings > Account > Devices(설정 > 계정 > 기기)에서 그 요청을 코드로 승인합니다.

  4. 로그인 창에 Signed in as ...(이 이메일로 로그인됨)이 보일 때까지 기다립니다. 승인만으로는 자격 파일이 저장되었다는 보장이 없으므로 이 문구를 꼭 확인하세요.

  5. 이후 모든 aside 명령에 같은 ASIDE_CLI_AUTH_PATH를 적용합니다. 새 셸이나 에이전트 도구 호출은 이전 셸의 설정을 물려받지 않습니다.

주의: 자격 파일은 출력, 업로드, 공유, 커밋(코드 저장소에 올리기)을 하지 마세요. 공개 폴더나 임시 폴더에도 두지 않습니다. 환경이 자격 저장을 허용하지 않으면 우회하지 말고 중단하세요.

참고로 변수를 정하지 않으면 자격 파일은 기본 위치 ~/.aside/cli/auth.json에 저장됩니다. ASIDE_HOME은 이 경로를 바꾸지 않고, ASIDE_CLI_AUTH_PATH도 설치 위치나 다른 설정 파일을 옮기지 않습니다. 승인 뒤 폴더 생성 단계에서 ENOENT나 EACCES 오류가 나면 저장소 문제를 먼저 해결하고, 새 로그인으로 새 코드를 승인하세요.

17.4 브라우저 작업 실행과 세션 이어가기

터미널에서 바로 작업을 시킵니다.

aside "Open localhost:3000 and run a smoke test"

따옴표 안의 문장이 지시문입니다(예시는 "localhost:3000을 열고 간단한 동작 테스트를 해 줘"라는 뜻). 이미 있는 세션을 이어갈 때는 session resume을 씁니다. <session-id>에는 이어갈 세션의 ID를 넣습니다.

aside session resume <session-id> "Continue"

CLI 세션은 끝나고 약 15분 뒤 제거되며, 브라우저의 채팅 목록에도 나타나지 않습니다. 보존하려면 다음 중 하나를 합니다.

  • 터미널: aside settings save-sessions true
  • 화면: Settings > Developers > Save sessions(CLI와 MCP 에이전트 세션을 채팅 목록에 남김)

예외로 aside mcp --computer-use는 서버마다 작업 하나를 항상 목록에 남깁니다.

17.5 계정 명령

한 컴퓨터에서 Aside 계정 여러 개에 로그인했다면, CLI 명령은 선택된 계정 하나로 실행됩니다.

명령 하는 일
aside account list 이 기기의 계정 목록. 현재 계정에 * 표시
aside account status 현재 계정 상태 (aside account status u1처럼 ID로 지정도 가능)
aside account use u1 이후 명령의 기본 계정 지정
--account u1 한 번만 특정 계정으로 실행. aside와 aside exec에서 사용 
aside --account u1 "Summarize the current page"
aside exec --account u1 -m openai-codex/gpt-5.5 "Plan this workflow"

선택한 계정이 로그아웃 상태면 CLI가 경고와 복구 방법을 알려 줍니다. 내가 연결한 외부 제공자 키(OpenAI, Anthropic)는 계속 쓸 수 있지만, Aside 기본 제공 모델은 로그인이 되어 있어야 합니다. Settings > Account에서 다시 로그인하거나, aside account use <id> 또는 --account <id>로 로그인된 다른 계정으로 바꾸세요.

17.6 MCP: 다른 AI 도구에서 Aside 쓰기

aside mcp를 실행하면 Aside가 MCP 서버가 되어, 다른 에이전트나 코딩 도구가 Aside의 브라우저 기능을 부를 수 있습니다.

aside mcp

mcp.json 설정을 지원하는 도구라면 다음을 추가합니다.

{
  "mcpServers": {
    "aside": {
      "command": "aside",
      "args": ["mcp"]
    }
  }
}

개발자 설정에서 CLI의 구체적인 경로를 찾아 준 경우에는 command에 그 경로를 넣으세요. 지원되는 코딩 도구에는 Aside가 브라우저 자동화 설정을 대신 설치해 줄 수도 있습니다.

17.7 REPL: 직접 브라우저 조작하기

페이지를 직접 들여다보거나, 스크린샷과 다운로드, 정해진 순서의 브라우저 단계가 필요할 때 씁니다.

aside repl "const p = await openTab('https://example.com')"

17.8 Remote Control (PRO)

Remote Control은 다른 기기에서 이 기기로 작업을 보내는 기능입니다. 화면 설명대로 "작업은 여기서 실행되고, 로그인과 브라우징은 이 컴퓨터에 남습니다." 내 컴퓨터에 로그인되어 있는 사이트를 그대로 쓰면서 원격으로 지시할 수 있다는 뜻입니다. 외부 비서(16.9)도 이 기능으로 내 브라우저에 닿습니다.

  1. Settings > Developers에서 Remote Control(Allow remote sessions on this machine)을 켭니다.

  2. 준비되면 Ready for remote sessions 아래에 이 기기 이름과 사용 명령이 표시됩니다.

  3. 다른 기기에서 CLI에 로그인(17.3)한 뒤 다음처럼 보냅니다. {host}에는 이 기기 이름을, <your prompt>에는 지시문을 넣습니다.

    aside exec --host "{host}" "<your prompt>"

  4. 대상 기기는 aside host list로 확인합니다. 이 기기는 online이어야 하며, disabled면 Remote Control이 꺼진 것이고 offline이면 Aside가 실행 중이 아닙니다.

  5. 매번 --host를 쓰기 싫으면 aside host use "{host}"로 기본 호스트를 지정할 수 있습니다.

참고: Remote Control 자체를 다룬 공식 도움말 페이지는 없습니다. 위 절차는 화면 문구와 비서 연결 문서(Connect dots 등)의 명령을 바탕으로 정리했습니다.

주의: Remote Control이 켜져 있는 동안 이 컴퓨터는 Aside가 실행 중이어야 하고, 잠자기나 종료 상태에서는 받을 수 없습니다. 연결한 외부 계정이 내 로그인 상태를 쓸 수 있다는 점도 기억하세요. 안전 원칙은 21장을 참고하세요.

18. 요금제, 크레딧, 여러 기기

이 장에서 할 일: 플랜과 크레딧이 어떻게 계산되는지 이해하고, 여러 컴퓨터에서 Aside를 쓸 때 무엇이 따라오고 무엇이 남는지 파악합니다.

18.1 플랜 비교

Settings > Plan & Usage(설정 > 플랜 및 사용량)에서 플랜, 크레딧, 결제 수단, 청구서를 확인합니다. 플랜은 세 가지입니다.

플랜 포함 내용
Free 월 500 크레딧, 루틴 최대 3개, 기본 제공 비밀번호 관리자, 개인화 메모리
Pro Free의 모든 것, Free의 3배 사용량, Ultrabrowse, 루틴 무제한, 가능한 경우 우선 모델 이용
Max Pro의 모든 것, Free의 40배 사용량, 얼리 액세스(먼저 써 보는) 프로그램

Pro와 Max는 결제에서 해당 가격이 활성화되어 있으면 월간 또는 연간 가격을 고를 수 있습니다. 가격 금액은 이 매뉴얼에 적지 않습니다. 최신 금액은 Aside 화면에서 확인하세요. 또 Channels의 Personal Assistants와 Remote Control에는 PRO 표시가 붙어 있습니다(16장, 17장).

18.2 크레딧

크레딧은 Aside가 제공하는 모델로 작업할 때 쓰는 사용량 단위입니다. 플랜은 결제 기간마다 크레딧을 줍니다. Settings > Plan & Usage > Credits에는 남은 크레딧 비율, 갱신일, 현재 플랜의 월 크레딧이 표시됩니다.

언제 새로 채워지나

  • 유료 플랜: 구독의 결제 기념일에 갱신됩니다. 체험 기간과 그 뒤 첫 유료 기간은 크레딧이 따로 지급됩니다.
  • Free 플랜: 매월 UTC 1일에 갱신됩니다. 한국 시간으로는 같은 날 오전 9시입니다.

얼마나 차감되나

크레딧 요율은 모델과 속도에 따라 다릅니다. 같은 작업이라도 더 큰 모델, Fast 모드, 긴 대화에서는 더 많이 듭니다. 실제 차감은 Settings > Plan & Usage > Aside credits usage에서 확인합니다.

참고: 크레딧은 Settings > Models에서 직접 연결한 API 키나 외부 AI 구독과는 별개입니다. 내 API 키를 쓰면 사용료는 해당 제공자 계정으로 청구될 수 있습니다(12장).

사용 내역 보기

Aside credits usage는 작업과 모델별로 크레딧 사용을 보여 줍니다. 행마다 날짜, 작업, 모델, 크레딧 양이 나옵니다.

  1. 월과 연도 선택기로 보고 싶은 달을 고릅니다.
  2. 필요하면 Download CSV를 눌러 그 달 내역을 파일로 받습니다.

추가로 구매한 크레딧

월 플랜 크레딧과 별도로 Buy credits로 크레딧(add-on)을 살 수 있습니다. 규칙은 네 가지입니다.

  1. 구매한 크레딧은 만료되지 않습니다. 구매 후 기한이 없습니다.
  2. 쓰지 않은 구매 크레딧은 월 크레딧이 갱신될 때 이월됩니다. 쓰지 않은 월 플랜 크레딧은 이월되지 않습니다.
  3. Pro나 Max를 해지하거나 Free로 내려도 구매 크레딧은 계속 쓸 수 있습니다. 다만 유료 플랜의 기능은 유지되지 않습니다.
  4. 월 플랜 크레딧을 먼저 쓰고, 다 쓰면 구매 크레딧을 씁니다.

Auto-reload

Auto-reload는 잔액이 부족해지면 크레딧을 자동으로 구매하는 기능입니다. Configure에서 설정합니다. 자동 결제가 일어나므로, 켜기 전에 Configure 화면에서 조건을 직접 확인하세요. 세부 항목(기준 잔액, 구매 단위 등)은 공식 도움말에 설명이 없습니다.

친구 초대

Plan & Usage와 Settings > General, 새 탭 오른쪽 위의 Invite friends에서 친구를 초대할 수 있습니다. 화면 문구는 "가입 후 둘 다 100 크레딧을 받습니다(You both get 100 credits after signup)"입니다. 세부 조건은 공식 도움말에 설명이 없으니 초대 화면의 안내를 따르세요.

18.3 플랜 바꾸기와 결제 관리

Settings > Plan & Usage에서 다음을 할 수 있습니다.

  • Adjust plan: 플랜 변경
  • 결제 수단 옆 Open: 결제 정보와 청구서를 Stripe(외부 결제 서비스) 화면에서 관리
  • 현재 크레딧 사용량 확인

유료 구독을 기간 말에 해지하도록 해 두면 Plan & Usage에 해지 예정일이 표시됩니다.

어떤 플랜이 맞을까요? 월 크레딧이 더 필요하거나, 자료가 많은 조사에 Ultrabrowse를 쓰고 싶거나, 루틴을 3개보다 많이 돌리고 싶으면 Pro를 고려하세요. 가장 큰 크레딧과 얼리 액세스가 필요하면 Max입니다.

18.4 여러 기기에서 쓰기

같은 계정으로 두 컴퓨터에 로그인하면 두 컴퓨터가 같은 Aside 계정에 연결되지만, 모든 것이 복사되지는 않습니다. 무엇이 따라오고 무엇이 남는지 구분해 두세요.

동기화되는 것

데이터 동기화 방식 확인 위치
북마크, 방문 기록, 열린 탭, 탭 그룹, 고정 탭, 동기화 대상 웹사이트 쿠키 브라우저 동기화. 로그인되어 있으면 켜짐 Settings > Account > Devices
Aside Vault 비밀번호 Vault 동기화. 비밀번호 관리자에 로그인되어 있으면 켜짐 Settings > Passwords

브라우저 동기화는 Aside가 계정 단위로 보관하는 동기화 키로 암호화됩니다. 새 탭에 Browser sync needs attention이 보이면 19장의 문제 해결을 참고하세요. 동기화되는 쿠키에는 업무용 사이트를 포함한 로그인 세션이 있을 수 있습니다. 모든 쿠키가 동기화 대상은 아니라서, 다른 컴퓨터에서 다시 로그인해야 하는 사이트도 있습니다.

각 컴퓨터에만 남는 것

macOS는 ~/.aside, Windows는 %USERPROFILE%\.aside 폴더에 저장되며 동기화되지 않습니다.

  • 채팅과 작업 기록
  • 메모리, 직접 만든 스킬, 에이전트 지침 파일(AGENTS.md, SOUL.md)
  • Aside에서 만든 프로젝트
  • 루틴과 실행 기록, 결과물
  • 작업이 만들었거나 내가 연결한 작업 폴더
  • 설정(에이전트 권한, 모델 선택 포함)
  • Context Awareness 기록(Settings > Memory)

한 컴퓨터에서 시작한 작업은 그 컴퓨터에서 계속 실행됩니다. 다른 컴퓨터에서 Aside를 열면 그 컴퓨터 자신의 채팅만 보입니다.

주의: 컴퓨터가 잠자기나 종료 상태가 되면 로컬 루틴과 기기 연결형 채널(예: Telegram 봇)이 멈춥니다. 유료 플랜이어도 마찬가지입니다. 루틴과 채널을 쓸 컴퓨터는 켜 두고, 인터넷에 연결하고, Aside를 실행해 두세요.

Cloud handoff

Cloud handoff는 Coming Soon(곧 제공 예정)이며, Pro 구독으로도 켜지지 않습니다. 클라우드 루틴이나 클라우드 브라우저에서 사이트에 로그인하는 정식 설정은 아직 없습니다. 실행 중인 로컬 작업, 채팅, 메모리, 작업 폴더를 다른 컴퓨터나 클라우드로 옮기는 공식 방법도 아직 없습니다.

18.5 새 컴퓨터로 옮기기

  • Aside에는 채팅과 작업 기록의 백업과 복원 기능이 아직 없습니다.
  • Aside 폴더를 새 컴퓨터로 복사하는 방법은 지원되지 않습니다. 일부 데이터가 컴퓨터의 보안 칩에 묶인 키로 암호화되어 있어서, 복사해도 새 하드웨어에서 열리지 않습니다.
  • 새 컴퓨터에서 로그인하면 18.4 표의 동기화 데이터가 알아서 따라옵니다.
  • 옛 컴퓨터를 정리하기 전에, Aside를 종료한 상태에서 .aside 폴더를 사본으로 보관해 두세요. 나중에 복원 기능이 생길 때를 대비한 것입니다.

따라서 새 컴퓨터로 옮길 때는 다음 순서를 권합니다.

  1. 옛 컴퓨터에서 중요한 스킬, 지침 파일, 프로젝트 폴더의 사본을 따로 챙깁니다(공식 절차는 아니고, 새 컴퓨터에서 다시 설정할 때 참고하기 위한 준비입니다).
  2. Aside를 종료하고 .aside 폴더 전체를 외장 저장 장치 등에 복사해 보관합니다.
  3. 새 컴퓨터에서 같은 계정으로 로그인합니다.
  4. 북마크, 기록, 탭, Vault 비밀번호가 따라왔는지 확인합니다.
  5. 모델, 권한, 루틴, 프로젝트는 새로 설정합니다.

증상을 아래 질문에서 찾아 보세요. 대부분은 설정 한두 군데를 확인하면 풀립니다. 복구 작업처럼 위험한 절차는 이 매뉴얼에 요약만 싣고, 세부 단계는 공식 문서 링크로 안내합니다.

19.1 작업이 막혔을 때

Q1. 작업이 멈춰 있고 아무 일도 안 일어납니다. 무엇을 확인하나요?

작업이 나를 기다리는 경우가 가장 많습니다. 승인이나 답변을 기다리는 상태일 수 있습니다.

  1. 해당 작업을 엽니다.
  2. 입력 요청이나 승인 요청을 찾습니다.
  3. 요청한 행동이 무엇인지 읽습니다.
  4. 승인하거나, 거절하거나, 질문에 답합니다.
  5. 화면에 재개(resume) 버튼이 있으면 누릅니다.

승인 팝오버는 브라우저 화면에서 바로 승인하거나 거부할 수 있습니다. 질문이나 초안 검토는 작업 상세 화면이 열립니다. 작업 상태는 승인 대기, 답변 대기, 오류, 완료처럼 눈에 보이게 표시됩니다.

팁: 로그인 화면에서 MFA(추가 인증), 패스키 승인, CAPTCHA, 본인 확인이 나오면 그 단계는 사람이 직접 마치고, 그다음 작업을 재개하세요. 저장된 로그인 정보로 하는 자동 입력은 Aside가 합니다.

Q2. 작업이 엉뚱한 방향으로 가고 있습니다. 어떻게 바로잡나요?

후속 지시(follow-up)를 보냅니다. 두 가지 방식이 있습니다.

방식 언제 쓰나요
Steer 지금 진행 중인 실행을 바로 고쳐야 할 때
Queue 지금 실행이 끝난 뒤에 해도 되는 지시일 때

예시 지시문입니다.

결제 페이지는 그만 보고, 대신 청구서 페이지를 사용해 주세요. 이메일은 절대 보내지 마세요.

기본 동작은 Settings > Agents(설정 > 에이전트)의 Follow-up behavior(후속 지시 동작)에서 정합니다. 이 매뉴얼을 만든 계정의 값은 Queue였습니다(2026-11-17 화면 기준).

Q3. "알림을 기다리는 작업"은 무슨 뜻인가요?

Aside는 알림이 올 때까지 작업을 잠시 멈춰 둘 수 있습니다. 작업을 열어 보면 내 답변이나 승인이 필요한지, 연결된 앱의 이벤트를 기다리는 중인지 알 수 있습니다.

Q4. 에이전트 탭(Agent Tabs)이 세로 사이드바에 안 보입니다.

고장이 아닐 수 있습니다. 레이아웃마다 보이는 방식이 다릅니다.

경우 어디에 보이나요
앱 안에서 시작한 채팅 그 채팅을 열면 나오는 브라우저 탭 미리보기. 세로 사이드바에는 Agent Tabs 줄이 생기지 않습니다
CLI나 MCP로 연결한 외부 에이전트 세로 사이드바의 Agent Tabs 그룹에 모여 보입니다
가로 탭 Agent Tabs 칩에 앱 채팅 탭과 외부 에이전트 탭이 함께 보일 수 있습니다

Appearance에는 Agent Tabs 표시 스위치가 없습니다. Settings > Agents의 정리 타이머(Clean up agent tabs)는 놀고 있는 탭을 언제 닫을지만 정하며, 보이는 위치와는 관계가 없습니다. 레이아웃을 바꾸거나 재시작할 필요도 없습니다.

외부 에이전트 탭이 세로 사이드바에서 정말 빠졌거나, 채팅 미리보기에 열린 탭이 안 보이면 작업 ID, 탭 레이아웃, 스크린샷을 모아 19.6절 방법으로 신고하세요.

19.2 비밀번호와 로그인

Q5. 비밀번호 자동 입력이 뜨지 않습니다.

Settings > Passwords(설정 > 비밀번호)에서 순서대로 확인합니다.

  1. Use default password manager가 켜져 있는지 확인합니다. Aside가 비밀번호를 관리하게 하려면 켜 둡니다.
  2. Enable Autofill이 켜져 있는지 확인합니다.
  3. 시크릿 창이라면 Disable in incognito 설정을 확인합니다.
  4. Excluded domains(제외 도메인)에 해당 사이트가 들어 있지 않은지 확인합니다.
  5. 보안이 약한(insecure) 사이트라면 그 사이트에서 자동 입력을 허용했는지 확인합니다.

패스키, MFA, 여러 단계 로그인이 있는 사이트는 저장된 정보를 먼저 채우고, 보이는 인증 단계는 사람이 마친 뒤 다음 안내를 기다리면 됩니다.

Q6. 1Password 확장이 Aside에서 작동하지 않습니다.

1Password는 Aside를 크로미움 기반 브라우저로 알아보지 못해서, 연결 파일을 직접 복사해야 합니다.

  1. 1Password 앱을 엽니다.
  2. Settings > Browser > Connect to additional browsers로 가서 Add browser를 누릅니다.
  3. Aside를 선택합니다.
  4. 아래 파일을 복사합니다.
원본: ~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.1password.1password.json
대상: ~/Library/Application Support/Aside/NativeMessagingHosts/com.1password.1password.json

참고: 공식 도움말은 위 경로를 macOS 기준으로만 안내합니다. Windows에서 같은 문제가 있으면 19.6의 방법으로 지원팀에 문의하세요.

Q7. Apple Passwords 확장이 작동하지 않습니다.

Aside에 공식 도움말의 아래 문장을 그대로 입력하세요.

Use the Apple Passwords skill and check whether Apple Passwords is connected properly.

뜻은 "Apple Passwords 스킬을 사용해서 Apple Passwords가 제대로 연결되어 있는지 확인해 줘"입니다. Aside가 점검을 마치면 Apple Passwords 확장을 다시 열어 보세요. 이제 쓸 수 있어야 합니다.

Q8. Aside Vault 잠금이 풀리지 않습니다.

Vault 비밀번호는 Aside 계정 비밀번호와 별개입니다. 잠금 화면(툴바의 열쇠 아이콘 또는 Settings > Passwords)에서 Forgot password?를 누릅니다.

상황 할 일 결과
복구 키(12개 단어)가 있음 12단어를 입력하고 새 잠금 비밀번호를 설정 저장된 비밀번호가 그대로 유지됨
복구 키가 없음 Reset Aside Vault 선택 빈 Vault가 새로 생기고, 예전 Vault의 비밀번호는 복구 불가

복구 키는 aside-recovery-key로 시작하는 .txt 파일이나, Vault를 만들 때 쓴 이메일에서 찾아 보세요. 초기화는 reset my vault 입력, 이메일 코드, 새 비밀번호 설정, 새 복구 키 저장과 확인을 거칩니다. 마지막 Reset을 누르기 전에는 아무것도 바뀌지 않으므로, 그 전에 창을 닫으면 새 비밀번호와 새 복구 키는 쓸 수 없습니다.

주의: 초기화 뒤에도 새 비밀번호가 거부되면, 초기화한 계정과 같은 계정을 열고 있는지 Settings > Passwords의 계정·Vault 목록에서 확인하세요. Vault 자세한 내용은 14장을 보세요.

19.3 가져오기, 재생, 프로필

Q9. 다른 브라우저에서 가져오기(import)가 실패합니다.

  1. 원래 브라우저의 프로필이 아직 있는지 확인합니다.
  2. 가져오기가 독점 접근을 요구하면 원래 브라우저를 닫습니다.
  3. 파일 가져오기만 되는 소스는 파일로 가져옵니다.
  4. 다시 시도합니다.

Windows에서는 Chrome이 마지막 창을 닫아도 계속 실행 중이라서 "Chrome을 닫으세요"가 반복되는 일이 많습니다. 작업 관리자를 열고 Google Chrome 프로세스를 모두 종료한 뒤 Try again을 누르세요. 프로세스가 하나도 없다면 Windows를 재시작하고, Chrome을 열기 전에 가져오기부터 실행하세요. Chrome에서 새 Aside 프로필을 만들다가 쿠키 복사에서 실패할 때도 같은 방법입니다.

화면에 나올 수 있는 오류 문구는 다음과 같습니다.

  • Browser import is unavailable in this version of Aside.
  • Browser import failed.
  • Please upload a ZIP file (Safari ZIP 가져오기)
  • Failed to read the ZIP file (읽을 수 없는 Safari ZIP)

Q10. 넷플릭스나 프라임 비디오 같은 스트리밍 사이트가 재생되지 않거나 "지원하지 않는 브라우저"라고 나옵니다.

저작권 보호 모듈(Widevine)이 오래됐거나 아직 내려받는 중일 때 생깁니다(예: 프라임 비디오 오류 코드 7132).

  1. 주소창에 aside://components를 입력해 엽니다.
  2. Widevine Content Decryption Module을 찾습니다.
  3. Check for update를 누릅니다.
  4. 상태가 Up-to-date로 바뀔 때까지 기다립니다.
  5. 스트리밍 탭을 새로 고칩니다.

Q11. 한 계정을 여러 브라우저 프로필에서 써도 되나요? 로그아웃은 어떻게 되나요?

됩니다. 한 컴퓨터에서 Aside 계정 하나는 그 계정으로 로그인한 모든 프로필이 공유합니다. 두 번째 프로필이 로그인하면 같은 계정에 합류하고, 채팅, 프로젝트, 루틴, 메모리도 같은 것이 보입니다.

  • 채팅은 실행된 프로필을 기억합니다(탭과 로그인이 그 프로필에 있기 때문입니다). 쉬고 있는 채팅을 다른 프로필에서 열면 그 프로필로 옮겨집니다.
  • 다른 프로필에서 아직 실행 중인 채팅에는 This task is running in another browser profile.가 뜨고 Open in <프로필> 버튼으로 이동합니다.
  • Settings > Account > Sign out은 현재 프로필에만 적용됩니다. 다른 프로필이 계정을 쓰는 동안에는 Sign out this profile?가 뜨고 계정은 그대로입니다. 마지막 프로필까지 로그아웃하면 컴퓨터에서 계정이 로그아웃됩니다.
  • 다른 프로필은 로그인돼 있는데 한 프로필에 You're using Aside in local mode가 보이면, 그 프로필에서 로그인하세요. 새 계정을 만들지 않고 기존 계정에 연결되며 채팅과 루틴도 함께 보입니다.

19.4 큰 문제: 동기화와 로컬 서비스

Q12. "Browser sync needs attention"(브라우저 동기화 확인 필요)가 뜹니다.

새 탭에 이 문구가 뜨거나 Settings > Account > Browser data recovery에 This device has no sync key가 보이는 경우입니다. 북마크, 방문 기록 같은 동기화 데이터를 푸는 열쇠(sync key)가 이 기기에도 Aside에도 아직 없다는 뜻입니다. 아래 순서대로 시도하세요. 위쪽일수록 내 데이터를 더 많이 지킵니다.

  1. 동기화가 잘 되는 다른 기기에서 Aside를 엽니다. 그 기기가 열쇠를 Aside에 넘겨줍니다. 그 기기의 Settings > Account를 열면 바로 됩니다. 그다음 이 기기의 Aside를 완전히 종료했다가 다시 엽니다.
  2. 복구 키를 씁니다. Settings > Account의 Browser data recovery에서 Recover를 누르고 가입 때 저장한 12단어 복구 키를 입력합니다.
  3. 계정 비밀번호를 씁니다. 2026년 9월 이전에 만든 계정은 Aside 계정 비밀번호가 있습니다. 복구 키 화면에서 I don't have my recovery key를 선택해 입력합니다.
  4. 브라우저 동기화를 초기화합니다. 위 방법이 모두 안 되면 I don't remember my password, Email me a code를 차례로 선택하고 이메일로 온 코드를 입력합니다. 초기화하면 이 기기의 북마크와 방문 기록은 남아 다시 동기화되지만, 이전 동기화에만 있던 데이터는 삭제되고, 이 계정으로 로그인한 모든 기기가 새 동기화로 옮겨집니다. Aside Vault와 로그인은 영향이 없습니다.

어떤 방법이든 끝난 뒤에는 Aside를 종료했다가 다시 열어야 동기화가 재개됩니다.

주의: 동기화를 고치려고 Aside 계정을 삭제하지 마세요. 계정을 삭제하면 복구 키나 계정 비밀번호로 되살릴 수 있던 동기화 데이터도 함께 지워집니다.

Vault 복구 키를 바꾸려는데 Restore browser sync before changing your recovery key가 나오면, 2026년 9월 이전 계정은 같은 12단어 키가 브라우저 동기화도 풀기 때문입니다. 위 순서로 동기화를 먼저 복원한 뒤 복구 키를 다시 바꾸세요.

Q13. Something went wrong. Aside can't connect to its local service.가 뜨고 설정과 채팅이 열리지 않습니다.

설정과 채팅이 로딩되지 않고, 루틴이 사라진 것처럼 보이며, 로컬 서비스가 10초에서 30초마다 재시작된다면 이 경우입니다. 로그는 .aside/logs/daemon-YYYY-MM-DD.log에 있고, 같은 줄이 [Installation] failed to initialize IK로 반복됩니다. 로컬 서비스가 이 컴퓨터에서 데이터를 지키는 열쇠를 열거나 만들지 못했다는 뜻입니다.

주의: 앱을 다시 설치해도 해결되지 않습니다. 열쇠가 앱 바깥에 있기 때문입니다. 원인을 알기 전에는 로그아웃, 재설치, 열쇠 초기화를 하지 마세요. 열쇠를 새로 만들면 예전 열쇠로 지키던 암호화 데이터를 읽을 수 없게 될 수 있습니다. 확실하지 않으면 먼저 지원팀(support@aside.com)에 문의하세요.

원인에 따라 복구 방법이 다릅니다(안전한 확인 단계, 설치 키 복구용 repair-installation 파일, Windows 전용 막힌 키 정리). 이 매뉴얼에서는 절차를 옮기지 않습니다. 로그에 찍힌 오류 문구를 확인한 뒤 공식 문서의 해당 항목만 따르세요.

  • 공식 문서: Aside keeps restarting or can't connect to its local service

지원팀에 보낼 때는 Aside를 종료하고 .aside 폴더를 안전한 곳에 복사해 둔 뒤, 문제가 생긴 날의 daemon 로그를 함께 보냅니다.

19.5 기능이 안 될 때

Q14. Computer Use(컴퓨터 사용)가 안 됩니다.

Computer Use는 이 컴퓨터의 앱을 읽고 조작하는 기능이며, macOS와 Windows에서 이 컴퓨터에서 도는 작업에만 쓸 수 있습니다.

  1. Settings > Agents에서 Computer Use를 켭니다.
  2. macOS에서는 System Settings > Privacy & Security에서 Aside에 Accessibility(손쉬운 사용)와 Screen Recording(화면 기록)을 허용합니다. 허용하면 Aside가 바로 인식합니다.
  3. 작업을 이 컴퓨터에서 실행합니다. 클라우드나 Remote Control로 다른 기기에서 도는 작업은 쓸 수 없습니다.

이용 조건도 확인하세요. 공식 변경 이력에 따르면 Computer Use는 공개 당시(v1.26.1023.5, 2026-10-23) Max 구독자와 실험 계정에 제공되었고, v1.26.1030.151(2026-10-30)부터는 Max가 필요한 경우 설정 화면이 그 사실을 안내합니다. 켜지지 않으면 Settings > Agents의 안내 문구부터 읽어 보세요.

Q15. CLI에서 Cannot open Windows installation key aside.install.sig 오류가 납니다.

CLI는 Aside를 실행하는 Windows 사용자의 키로 로그인합니다. 이 오류는 명령이 다른 Windows 사용자로 실행됐다는 뜻이며 키 자체는 멀쩡합니다. 키 초기화, 로그아웃, 재설치는 하지 마세요.

  • Codex 같은 코딩 에이전트가 자기 샌드박스(별도 Windows 계정) 안에서 명령을 실행했다면, 에이전트가 aside를 샌드박스 밖에서 실행해도 되는지 물을 때 승인하거나 직접 실행하세요.
  • 다른 사용자로 연 터미널(다른 관리자 계정의 권한 상승 창 포함)이나 원격 세션이라면 닫고, Aside를 쓰는 같은 Windows 사용자의 일반 PowerShell 창에서 다시 실행하세요.

CLI 자세한 내용은 17장을 보세요.

19.6 버그 신고와 성능 문제 보고

버그 신고

이메일 support@aside.com로 보냅니다. 아래를 함께 적어 주세요.

  • 대략적인 시간
  • 관련된 웹사이트나 앱
  • 기대한 결과

  • 스크린샷이나 결과 파일 경로(있으면)
  • 화면에 보인 오류 메시지

앱 안에서 보내는 방법(Send feedback)도 두 가지입니다.

  1. Settings를 열고 Send feedback을 선택합니다.
  2. 작업 상세 화면에서 더보기(more actions) 메뉴를 열고 Send feedback을 선택합니다.

일반 피드백에는 스크린샷을 붙일 수 있고, 작업 피드백에는 작업 기록(transcript)과 진단 정보를 포함할 수 있습니다. 2026-11-01 업데이트로 Send feedback에서 분류를 고르고, Aside 문서를 먼저 검색하고, 현재 서비스 상태도 볼 수 있게 되었습니다.

성능 문제 보고

느려지거나 멈추는 문제는 아래 두 가지 자료를 support@aside.com으로 보내면 원인을 찾는 데 도움이 됩니다.

  1. 히스토그램 데이터 내려받기: 주소창에 aside://histograms를 열고 Download를 눌러 .txt 파일을 저장합니다. 크기는 보통 3MB에서 10MB 정도입니다.
  2. 성능 추적(trace) 녹화: 불필요한 탭을 닫고 aside://tracing을 열어(열리지 않으면 aside://chrome-urls/?host=chrome://tracing/#internal-debug-pages에서 Enable debugging pages를 누릅니다) 녹화(Record)한 뒤, 문제가 있는 사이트에서 증상을 재현하고 곧바로 Stop, Save로 .pftrace.gz 파일을 저장해 보냅니다. 파일 이름이나 확장자는 바꾸지 마세요.

추적 녹화의 상세 설정값(카테고리 목록 등)은 길어서 옮기지 않습니다. 공식 문서의 Report a performance issue 항목을 그대로 따라 하세요.

20. 실전 활용 레시피 10선

이 장에서 할 일: 복사해서 바로 쓸 수 있는 지시문 10개로 Aside에 실제 업무를 맡겨 봅니다.

20.0 먼저 익힐 공통 공식

Aside에 일을 맡길 때는 아래 다섯 칸을 채우면 결과가 안정됩니다. 모든 레시피가 이 공식으로 만들어져 있습니다.

칸 무엇을 적나요 예
[목표] 끝났을 때 무엇이 되어 있어야 하나요 경비 정리 시트 한 장
[입력] 어디의 무엇을 재료로 쓰나요 다운로드 폴더의 영수증 PDF
[제약] 하지 말아야 할 것, 범위, 멈출 곳 메일은 보내지 말고 초안까지만
[산출물] 어떤 모양으로 받고 싶나요 표(날짜, 가게, 금액), 출처 링크 포함
[검증] 끝났다고 말하기 전에 무엇을 확인하나요 합계를 원본과 대조하고 안 맞는 줄은 표시

팁: 외부로 나가는 행동(발행, 발송, 결제)이 걸려 있으면 [제약]에 "초안까지만" 또는 "이 단계에서 멈추고 나에게 물어보기"를 꼭 넣으세요. 안전 원칙은 21장에 정리했습니다.

각 레시피의 구성은 같습니다: 상황, 시키는 말, 멈춤 지점(사람이 확인할 곳), 결과 확인 방법, 응용 팁.

20.1 열어 둔 긴 글 요약과 핵심 표 (사이드 패널)

상황: 긴 기사나 보고서를 읽는 중인데, 시간이 없어서 핵심과 숫자만 먼저 보고 싶습니다. 사이드 패널(7장)은 보던 페이지 옆에서 바로 묻는 용도입니다.

시키는 말: 해당 페이지에서 사이드 패널을 열고(Mac ⌥⇧B, Windows Alt+Shift+B) 입력합니다.

[목표] 지금 열어 둔 이 글을 5분 안에 이해할 수 있게 정리해 줘.
[입력] 현재 탭의 글 전체.
[제약] 글에 없는 내용은 추가하지 말고, 추측은 "추측"이라고 표시해.
[산출물] 1) 세 줄 요약 2) 핵심 주장 5개와 근거를 담은 표(주장, 근거, 글 속 위치) 3) 글에 나온 숫자와 날짜 목록.
[검증] 표의 숫자는 원문과 다시 대조하고, 확인이 안 되는 항목은 "확인 필요"로 표시해.

멈춤 지점: 없습니다(읽기만 하는 작업). 다만 요약을 다른 곳에 올리거나 공유하기 전에는 직접 읽어 보세요.

결과 확인 방법: 표의 "글 속 위치"를 보고 원문의 서너 군데를 직접 찾아 숫자가 맞는지 대조합니다.

응용 팁: 마음에 드는 형식이 생기면 "다음부터 긴 글은 이 형식으로 정리해"라고 말해 두세요. 두 번 이상 반복되면 스킬(20.9, 9장)로 만들 때입니다.

20.2 경쟁 서비스 3곳 가격과 기능 비교 (Ultrabrowse)

상황: 도입을 검토하는 서비스 3곳의 가격과 기능을 비교표로 만들고 싶습니다. 여러 사이트를 오가는 깊은 조사는 Ultrabrowse(깊은 조사 모드, 공식 문서 기준 Pro 이상)가 맞습니다.

시키는 말: 새 탭 Ask 모드나 채팅 입력창에서 Ultrabrowse를 켜고 입력합니다.

[목표] 아래 세 서비스의 가격과 기능을 비교해서 의사결정용 표를 만들어 줘: 서비스A, 서비스B, 서비스C (실제 이름으로 바꿔서 사용).
[입력] 각 서비스의 공식 사이트 가격 페이지와 기능 소개 페이지.
[제약] 공식 사이트에 적힌 내용만 쓰고, 가격이 안 보이면 "비공개"라고 적어. 기준 날짜를 표 위에 적어.
[산출물] 표(서비스, 요금제 이름, 월 가격, 핵심 기능 3개, 제한 사항) + 각 칸의 출처 링크 + 3줄 추천 의견.
[검증] 모든 가격과 기능 옆에 출처 링크를 붙이고, 링크를 열어 문구가 실제로 있는지 확인한 항목만 "확인됨"으로 표시해.

멈춤 지점: 가입, 문의 양식 제출, 결제는 시키지 않습니다. 가격 페이지가 로그인을 요구하면 로그인 단계에서 멈추게 하세요.

결과 확인 방법: 표에서 가격이 가장 중요한 칸 3개를 골라 출처 링크를 직접 열어 대조합니다.

응용 팁: "우리 상황(인원, 예산)에서 어느 요금제가 맞는지"를 후속 지시(Queue)로 이어서 물으면 비교가 의사결정으로 바뀝니다.

20.3 답장이 필요한 메일 정리와 답장 초안 (보내기 전 멈춤)

상황: 받은 편지함이 쌓였습니다. 답장이 필요한 메일만 골라 우선순위를 정하고 초안을 만들고 싶습니다.

시키는 말:

[목표] 받은 편지함에서 답장이 필요한 메일을 찾아 정리하고, 각각 답장 초안을 만들어 줘.
[입력] 최근 3일 동안 받은 메일(광고와 알림 메일은 제외).
[제약] 절대 메일을 보내지 마. 초안으로만 저장하거나 화면에 보여 줘. 내가 말하지 않은 약속이나 일정은 초안에 넣지 마.
[산출물] 표(보낸 사람, 제목, 답장이 필요한 이유, 마감 추정, 우선순위) + 우선순위 상위 5건의 답장 초안. 말투는 정중하고 짧게.
[검증] 표의 건수와 실제 받은 편지함의 해당 메일 수를 대조해서 빠진 메일이 없는지 알려 줘.

멈춤 지점: 발송 버튼은 사람이 누릅니다. 초안은 하나씩 읽고 수정한 뒤 직접 보냅니다.

결과 확인 방법: 메일함의 "보낸편지함"이 비어 있는지(새로 나간 메일이 없는지) 확인하고, 초안 보관함에 초안이 생겼는지 봅니다.

응용 팁: 답장 말투를 한 번 알려 주고 "내 말투로 써 줘"를 메모리(10장)에 저장해 두면 다음부터 반복할 필요가 없습니다. 메일이 많으면 날짜 구간을 나눠 요청해야 빠지는 메일이 줄어듭니다.

20.4 다운로드 폴더의 영수증 PDF로 경비 시트 만들기

상황: 한 달치 영수증 PDF가 다운로드 폴더에 쌓여 있습니다. 정산용 시트가 필요합니다.

시키는 말: 채팅 입력창의 + 메뉴에서 Attach folder로 폴더를 붙이거나, 폴더 접근을 허용한 뒤 입력합니다.

[목표] 영수증 PDF를 경비 정리 시트로 만들어 줘.
[입력] 다운로드 폴더 안의 이번 달 영수증 PDF 전부.
[제약] 원본 파일은 이동, 삭제, 이름 변경을 하지 마. 읽기만 해. 읽기 어려운 항목은 추측하지 말고 "판독 불가"로 표시해.
[산출물] 엑셀 파일 1개: 열은 날짜, 가게 이름, 합계, 결제수단, 원본 파일명. 맨 아래에 총합계.
[검증] 영수증 PDF 개수와 시트 행 수가 같은지 확인하고, 총합계를 다시 계산해서 보여 줘. 판독 불가 항목은 따로 목록으로 알려 줘.

멈춤 지점: 폴더 접근 권한 요청이 뜨면 필요한 폴더만 허용합니다(13장). 경비 시스템에 올리거나 제출하는 단계는 사람이 합니다.

결과 확인 방법: 시트를 열어 행 수와 파일 개수를 비교하고, 금액이 큰 영수증 2~3장은 원본 PDF와 직접 대조합니다.

응용 팁: 결과가 마음에 들면 "이 작업을 매달 같은 방식으로 할 수 있게 스킬로 만들어 줘"로 이어 가세요(20.9).

20.5 유튜브 영상 자막 요약으로 블로그 초안

상황: 참고할 영상의 핵심을 정리해 내 블로그 글의 뼈대를 만들고 싶습니다.

시키는 말:

[목표] 아래 유튜브 영상의 내용을 바탕으로 블로그 초안을 만들어 줘: (영상 주소)
[입력] 영상의 자막(한국어 자막이 있으면 그것을 사용).
[제약] 영상에 없는 사실은 쓰지 마. 영상의 문장을 그대로 길게 옮기지 말고 내 말로 바꿔 써. 영상 링크와 채널 이름을 출처로 글 끝에 적어.
[산출물] 제목 후보 3개, 소제목 4개로 이루어진 본문 초안(1,500자 안팎), 핵심 요약 3줄, 마지막에 독자에게 던지는 질문 1개.
[검증] 자막에 없는 주장이 들어갔는지 스스로 점검하고, 영상 속 숫자와 고유명사는 목록으로 따로 보여 줘.

멈춤 지점: 초안만 받습니다. 블로그에 올리는 일은 20.6의 임시저장 레시피로 별도로 진행합니다.

결과 확인 방법: 목록으로 받은 숫자와 고유명사를 영상의 해당 부분에서 직접 확인합니다. 자막이 자동 생성이면 오탈자가 있을 수 있습니다.

응용 팁: 영상 화면에만 나오는 표나 그림은 자막에 없습니다. 그런 내용이 중요하면 "화면의 내용도 확인해서 반영해"를 덧붙이되, 결과의 어느 부분이 화면에서 온 것인지 구분해 달라고 하세요.

20.6 블로그 에디터에 임시저장까지만 (발행 금지)

상황: 20.5에서 만든 초안을 블로그 편집기에 옮겨 두고, 발행은 내가 직접 하고 싶습니다.

시키는 말: 블로그 편집기 글쓰기 화면을 연 상태에서 입력합니다.

[목표] 아래 초안을 이 블로그 편집기에 입력하고 임시저장까지만 해 줘.
[입력] (초안 전체 붙여넣기)
[제약] 발행, 공개 설정 변경, 예약 발행은 절대 하지 마. 임시저장 버튼만 눌러. 제목과 본문이 모두 채워졌는지 입력한 뒤에 화면에서 확인하고 저장해.
[산출물] 편집기에 입력된 제목과 본문, 임시저장 완료.
[검증] 임시저장 후 "저장 목록" 화면을 열어 방금 저장한 글이 있는지 확인하고, 제목과 본문 첫 줄을 나에게 알려 줘. 발행되지 않았음도 함께 확인해 줘.

멈춤 지점: 발행 직전 화면에서 사람이 제목, 본문, 이미지, 공개 설정을 읽고 직접 발행합니다.

결과 확인 방법: 편집기의 "저장 목록" 화면에서 글이 보이는지 확인합니다. "저장했습니다" 같은 알림만 믿지 말고, 본문이 비어 있지 않은지 열어서 봅니다.

응용 팁: 편집기에 따라 제목은 채워졌는데 본문이 비어 있는 일이 있습니다. 본문 입력 후 저장 목록에서 글을 다시 열어 단락 구분과 첫 글자까지 확인하세요.

20.7 로그인이 필요한 사이트에서 서류 내려받기 (Vault, MFA는 사람이)

상황: 로그인해야만 받을 수 있는 서류(명세서, 증명서 등)를 매달 내려받습니다.

시키는 말:

[목표] (사이트 이름)에 로그인해서 이번 달 (서류 이름) PDF를 내려받아 줘.
[입력] 저장된 로그인 정보(Aside Vault의 자동 입력을 사용).
[제약] 비밀번호는 내가 알려 주지 않아. 저장된 로그인 정보로만 로그인해. 추가 인증(MFA), 인증번호, CAPTCHA가 나오면 멈추고 나에게 알려 줘. 서류 내려받기 외에 다른 설정이나 신청은 건드리지 마.
[산출물] 다운로드 폴더에 저장된 PDF 파일 1개와 파일 이름.
[검증] 내려받은 파일을 열어서 기간과 이름이 맞는지 확인하고 알려 줘.

멈춤 지점: MFA, 패스키 승인, 인증번호 입력은 사람이 직접 합니다. 화면에 보이는 인증 단계를 마친 뒤 작업을 재개하세요(19장 Q1). Vault 접근 승인 요청이 뜨면 내용을 읽고 승인합니다.

결과 확인 방법: 다운로드 폴더에서 파일을 열어 기간과 이름을 눈으로 확인합니다.

응용 팁: 사이트마다 같은 순서라면 로그인부터 내려받기까지를 스킬이나 루틴(11장)으로 만들 수 있습니다. 단, MFA가 있는 사이트는 루틴 도중 사람의 도움이 필요하다는 점을 감안하세요. 비밀번호를 지시문에 쓰는 것은 피하세요(21장).

20.8 매주 월요일 업계 뉴스 브리핑 루틴

상황: 매주 월요일 아침에 내 업계의 주요 뉴스를 요약해서 받고 싶습니다. 정해진 시각에 반복되는 일은 루틴(11장)이 맞습니다.

시키는 말: 채팅에서 먼저 한 번 실행해 결과를 확인한 뒤, 루틴으로 만듭니다.

[목표] 매주 월요일 오전 9시에 지난 7일간의 (업계 이름) 주요 뉴스 브리핑을 만들어 줘.
[입력] 신뢰할 수 있는 뉴스 사이트와 공식 발표 페이지 위주로 검색.
[제약] 기사 원문을 그대로 옮기지 말고 요약해. 모든 항목에 기사 제목과 링크를 붙여. 내가 하는 일(예: 중소기업 대상 영업)과 관련 있는 것을 우선해. 로그인이 필요한 사이트는 건너뛰어.
[산출물] 핵심 뉴스 5건(각 두 줄 요약, 내 업무에 주는 의미 한 줄, 링크) + 이번 주 한 줄 총평.
[검증] 링크가 열리는지, 기사 날짜가 지난 7일 안인지 확인하고 아닌 항목은 빼. 확인하지 못한 내용은 "확인 필요"로 표시해.

그다음 이어서 입력합니다.

이 작업을 매주 월요일 오전 9시에 실행하는 루틴으로 만들어 줘. 결과는 읽기만 하는 권한으로 실행해 줘.

멈춤 지점: 루틴을 만들기 전에 일정과 권한(Create routine 창의 Advanced > Permission)을 사람이 확인합니다. Free 플랜은 활성 루틴이 3개까지입니다. 뉴스를 메일로 보내거나 게시하는 단계는 넣지 않습니다.

결과 확인 방법: 루틴 화면(Settings > Routines)에서 일정 표시가 의도한 요일과 시각인지 확인하고, 처음 실행된 날 결과 채팅을 직접 열어 읽습니다. 일정이 시간에 맞게 실제로 한 번 돌아야 믿을 수 있습니다.

응용 팁: 첫 두세 주는 결과를 꼼꼼히 읽고 "이런 기사는 빼 줘" 같은 피드백으로 지시문을 다듬으세요. 루틴 결과를 읽지 않으면 틀린 요약이 그대로 쌓입니다(21장 원칙 6).

20.9 방금 한 반복 작업을 스킬로 만들기

상황: 같은 설명을 두 번째 하고 있습니다(예: 영수증 정리, 보고서 형식). 이제 스킬(9장)로 저장할 때입니다.

시키는 말: 작업이 한 번 잘 끝난 채팅에서 이어서 입력합니다.

[목표] 방금 한 이 작업을 다음에도 같은 방식으로 할 수 있도록 스킬로 만들어 줘.
[입력] 이 채팅에서 내가 한 지시, 네가 수정한 부분, 내가 고쳐 달라고 했던 점.
[제약] 개인 이름, 계정 정보, 비밀번호는 스킬에 넣지 마. 내가 승인해야 하는 단계(발송, 발행, 결제)는 스킬 안에서도 "멈추고 확인"으로 적어 줘.
[산출물] 스킬 이름, 언제 쓰는지 한 줄 설명, 단계별 절차, 멈춤 지점 목록.
[검증] 만든 스킬의 내용을 나에게 먼저 보여 주고, 내가 확인한 뒤에 저장해 줘.

멈춤 지점: 저장 전에 스킬 내용을 사람이 읽고 확인합니다.

결과 확인 방법: Settings > Plugins & MCPs > Skills의 My Skills에 새 스킬이 보이는지 확인하고, 새 채팅에서 짧게 호출해 같은 결과가 나오는지 시험합니다.

응용 팁: 스킬 이름은 "언제 쓰는지"가 한눈에 보이게 지으세요. 스킬이 맞는지 메모리가 맞는지 헷갈리면, 절차가 있는 작업은 스킬, 취향과 사실은 메모리로 구분합니다(10장).

20.10 웹 서비스 사용법을 캡처 매뉴얼로 만들기

상황: 팀원이나 고객에게 웹 서비스 사용법을 알려 주는 단계별 가이드를 만들고 싶습니다.

시키는 말:

[목표] (서비스 이름)의 (기능 이름) 사용법을 초보자용 단계별 매뉴얼로 만들어 줘.
[입력] 지금 열려 있는 서비스 화면. 내가 정한 순서: (1단계 ~ 마지막 단계 간단히).
[제약] 데이터를 만들거나 수정하거나 삭제하지 말고 화면만 보여 줘. 개인정보(이름, 이메일, 계좌)가 보이는 부분은 캡처에서 가리거나, 가릴 부분을 표시해서 알려 줘. 설정 변경, 결제, 발송은 하지 마.

[검증] 문서 순서대로 따라 했을 때 막히는 단계가 없는지 점검하고, 캡처에 개인정보가 남아 있지 않은지 확인해 줘.

멈춤 지점: 사람이 직접 해야 하는 단계(로그인, 결제, 인증번호)는 매뉴얼에 "사람이 직접" 표시를 넣게 합니다. 캡처를 외부에 나눠 주기 전 개인정보 여부를 사람이 한 번 더 봅니다.

결과 확인 방법: 문서를 열어 캡처가 번호 순서대로 있는지, 글과 그림이 맞는지 확인하고, 다른 사람 한 명이 따라 해 보게 합니다.

응용 팁: 이 레시피는 이 매뉴얼의 그림과 같은 방식입니다. 캡처 파일 이름 규칙(예: 01_로그인.png)을 지시문에 미리 적어 두면 정리가 쉽습니다.

21. 안전하게 쓰는 7가지 원칙

이 장에서 할 일: 실수가 돌이킬 수 없게 되기 전에 막는 일곱 가지 습관을 익힙니다.

Aside는 여러 사이트와 계정을 대신 다룹니다. 그래서 "무엇을 맡기고, 어디서 멈추고, 어떻게 확인하는가"가 가장 중요합니다.

원칙 1. 외부로 나가는 행동은 초안까지만, 그다음은 내 승인

발행, 발송, 결제, 게시, 신청처럼 밖으로 나가서 되돌리기 어려운 행동은 지시문 [제약]에 "초안까지만" 또는 "보내기 전에 멈추고 물어봐"를 넣습니다. 짧은 승인("응", "좋아")은 방금 제안한 한 단계에만 해당한다고 생각하세요. 다음 외부 행동은 그때 다시 승인합니다.

원칙 2. 완료는 실제 결과 화면으로 확인

"완료했습니다"라는 말이나 성공 알림은 증거가 아닙니다. 발행 글은 공개 주소로, 임시저장은 저장 목록으로, 메일은 보낸편지함이나 초안함으로, 파일은 폴더를 열어서 확인합니다. 상태가 애매하면 같은 행동을 다시 시키지 말고 먼저 현재 상태를 보세요. 중복 발송이나 중복 업로드를 막는 가장 쉬운 방법입니다.

원칙 3. 권한은 필요한 만큼만 (Guard가 기본)

입력창의 + > Permission에서 Read only(파일을 바꾸지 않고 살펴보기만), Guard(승인된 폴더에서 일하고 다른 폴더에 접근하기 전에 물어봄), Full access(컴퓨터 어디서나 읽고 씀)를 고릅니다. 조사나 요약은 Read only, 일반 업무는 Guard면 충분합니다. Full access는 꼭 필요한 작업에만 쓰고, 샌드박스(작업 범위를 제한하는 보호 장치)를 끄라는 확인이 나오면 이유를 읽고 결정하세요. 폴더 권한도 필요한 폴더만 허용합니다. 자세한 내용은 13장을 보세요.

참고: 공식 문서에 따르면 새 작업의 기본 권한 모드는 Guard입니다. 이 매뉴얼의 그림에 Full access가 보이는 것은 캡처한 계정에서 Settings > Agents의 Access permission을 바꿔 두었기 때문입니다. 이 값을 바꿨다면 안전을 위해 Guard로 돌려 두는 것을 권합니다.

원칙 4. 민감한 정보는 Vault로, 프롬프트에는 비밀번호를 쓰지 않기

비밀번호, 카드 번호, 인증 코드를 지시문이나 채팅에 직접 쓰지 마세요. 로그인은 Aside Vault의 자동 입력에 맡기면 AI에게 비밀번호가 보이지 않습니다(14장). 지시문에는 "저장된 로그인 정보로 로그인해"라고만 씁니다.

원칙 5. 결제와 계정 변경은 사람이

결제 수단 등록, 구독, 결제 승인, 비밀번호 변경, 계정 삭제, 권한 변경은 사람이 직접 합니다. 에이전트에게는 "결제 직전 화면에서 멈추고 알려 줘"까지만 시키세요.

원칙 6. 루틴 결과는 반드시 읽기

루틴은 내가 없을 때 돌기 때문에 틀려도 아무도 모릅니다. 처음 몇 번은 결과를 꼼꼼히 읽고, 이후에도 정기적으로 확인하세요. 일정이 제시간에 실제로 한 번 돌았는지 보기 전에는 "믿을 수 있다"고 말하지 마세요. 루틴에는 가능하면 읽기 전용 권한을 쓰고, 외부로 나가는 행동은 넣지 않습니다(11장).

원칙 7. 같은 설명을 두 번 하면 스킬이나 메모리로

같은 지시를 두 번 반복하고 있다면 저장할 때입니다. 절차가 있는 작업은 스킬(9장), 내 취향과 사실은 메모리(10장)에 저장합니다. 저장한 내용에 개인정보나 비밀번호가 들어가지 않았는지는 한 번 읽어 보세요.

원칙 한 줄 요약 지시문에 넣을 말
1 밖으로 나가는 일은 승인 후에 "초안까지만, 보내기 전에 멈춰"
2 결과 화면으로 확인 "끝나면 저장 목록(또는 폴더)을 열어 확인해서 알려 줘"
3 권한은 최소로 권한 Guard 또는 Read only
4 비밀번호는 Vault로 "저장된 로그인 정보로 로그인해"
5 결제와 계정 변경은 사람이 "결제 직전에 멈춰"
6 루틴 결과는 읽기 처음 3회는 직접 열어 보기
7 반복되면 저장 "이걸 스킬로 만들어 줘"

v1.0.1022.1
